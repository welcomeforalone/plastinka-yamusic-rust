# Инструкция для ИИ-агентов

> **For AI coding agents** (Claude Code, Codex, Cursor, Copilot, Gemini and
> others). Read this file fully before changing anything. Write code comments,
> commit messages and UI text in Russian; identifiers in English.

Этот файл читают ИИ-агенты, которые помогают людям готовить pull request в
Plastinka. Человеку он тоже полезен: здесь коротко всё, из-за чего PR
отклоняют. Подробнее о процессе — [CONTRIBUTING.md](CONTRIBUTING.md).

## Что за проект

Неофициальный клиент Яндекс Музыки. Десктоп на Rust (iced + wgpu, tokio,
rodio + symphonia) для Windows, Linux и macOS, отдельный Android-клиент на
Kotlin, Jetpack Compose и Media3 в `android/`. Лицензия GPL-3.0-or-later.

Прежде чем писать код, прочитай то, что относится к задаче:

- [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) — модули и как они связаны;
- [docs/FEATURES.md](docs/FEATURES.md) — как ведёт себя каждая функция ПК;
- [docs/ANDROID.md](docs/ANDROID.md) — то же для Android;
- [docs/BUILDING.md](docs/BUILDING.md) — сборка, проверки, тестовые хуки;
- [docs/api/](docs/api) — разобранные эндпоинты Яндекс Музыки и протокол
  «Слушать вместе». Новый эндпоинт сначала опиши там.

Поведение Android повторяет десктоп. Если они расходятся, прав десктоп.

## Жёсткие правила

PR, который нарушает любое из них, не принимается, даже если всё остальное
хорошо.

1. **Звук не пишется на диск.** Плеер держит поток только в памяти: никаких
   временных файлов, кэша треков, HTTP-кэша с аудио. Единственное исключение —
   явная кнопка «Скачать» в папку, которую выбрал пользователь, и только при
   активной подписке. На диск можно кэшировать метаданные и обложки.
2. **Музыка только с подпиской Плюс.** Плеер не создаётся и не запускается,
   пока не подтверждён Плюс (`account/status`). Ошибка запроса статуса — это
   не «подписка есть».
3. **Токен — только в системном хранилище паролей** (Windows Credential
   Manager, Secret Service, Keychain, Android Keystore). Не в файлах, логах,
   `Debug`, текстах ошибок и URL. Хранилище недоступно — токен не
   сохраняется, запасного файла нет.
4. **Запись в аккаунт — только по действию пользователя.** «Нравится», «Не
   нравится», правки плейлистов — только по нажатию. Автоматическая запись
   (например, «Не нравится» от Slopless) — только после отдельного согласия
   в диалоге.
5. **Чужой код и бренд.** Не переносить код официального клиента и проектов
   с несовместимой лицензией; код под GPL-3.0 можно, с указанием источника.
   Не использовать логотипы и фирменные шрифты Яндекса, не называть
   приложение «Яндекс Музыка». Имя — Plastinka.
6. **Данные уходят только туда, где это описано.** Новый хост, на который
   приложение ходит по сети, указывается в [THIRD-PARTY.md](THIRD-PARTY.md) и
   в описании PR. Телеметрии и аналитики нет и не будет.
7. **Новые зависимости — только с обоснованием** в PR и с совместимой
   лицензией (`cargo metadata --format-version 1`). Не подключай крейт или
   библиотеку ради пары строк.

## Правила кода (Rust)

- В рабочем коде запрещены `unwrap`, `expect`, `panic!`, `todo!`,
  `unimplemented!`, `unreachable!`, `dbg!`, `println!`/`eprintln!`,
  индексация и срезы (`v[i]`, `&s[a..b]`). Это закреплено линтами в
  `Cargo.toml`, clippy упадёт. Вместо них — `get`, `?`, `writeln!`. Не
  обходи линты через `#[allow]`.
- `unsafe` запрещён (`unsafe_code = "deny"`). Три исключения перечислены в
  `Cargo.toml`; новое — только с объяснением в PR, зачем без него нельзя.
- В тестах всё это можно, но только внутри `#[test]` и `#[cfg(test)]`. Каждый
  файл в `tests/` начинается с `#![cfg(test)]`.
- Никаких `as` с потерей данных: `try_from` и явная обработка.
- Ошибки сети и API не роняют приложение и не теряются молча: пользователь
  видит понятное сообщение на русском.
- В async-коде нет блокирующих вызовов (файлы, `std::thread::sleep`, тяжёлые
  вычисления — через `spawn_blocking` или вне async).
- Платформенный код — только под `#[cfg(...)]`. Код должен собираться на
  Windows, Linux и macOS.
- Тестовые хуки (`PLASTINKA_TEST_*`) работают только в отладочной сборке
  (`#[cfg(debug_assertions)]`) и ничего не сохраняют.

## Правила кода (Android)

- Без `!!` и необработанных исключений; ошибки сети — сообщение на русском.
- Токен только в заголовке запроса, никогда в логах и тексте ошибок.
- Звук — только поток в памяти, как на десктопе.

## Как работать

1. **Маленький и цельный PR.** Одна функция или одно исправление. Не
   переформатируй и не «улучшай» код, который не относится к задаче, не
   переименовывай чужие функции, не переставляй файлы.
2. **Сначала найди, как это уже сделано.** В проекте почти для всего есть
   образец: запросы к API — `src/api/`, сердце трека — `toggle_like` в
   `src/ui/library.rs`, настройки — `src/storage/config.rs`. Повторяй
   существующие подходы, не заводи параллельные.
3. **Не трогай без просьбы:** версию в `Cargo.toml` и `build.gradle.kts`,
   workflows в `.github/`, `LICENSE`, подпись Android, автообновление.
4. **Тесты.** Логику покрывай unit-тестами рядом с кодом. UI-тестов и
   скриншотов в проекте нет: интерфейс проверяет человек руками.
5. **Документация в том же PR.** Изменилось поведение — обнови
   `docs/FEATURES.md` (или `docs/ANDROID.md`), раздел «Тестовые сценарии» в
   `docs/BUILDING.md`, `README.md`, если это видно пользователю. Новый
   эндпоинт — спека в `docs/api/`: путь, параметры, пример ответа, ошибки,
   источник.
6. **Комментарии и коммиты — на русском.** Комментарий объясняет «почему», а
   не пересказывает код. Сообщение коммита — что изменилось для
   пользователя или кода, первая строка до 72 символов.

## Запуск приложения агентом

- Никогда не трогай настоящую запись пользователя в хранилище паролей.
  Запускай только с `PLASTINKA_KEYRING_SERVICE=plastinka-test`, а для
  проверок без входа — с `PLASTINKA_TEST_TOKEN` (фальшивый токен, только
  debug-сборка). Остальные хуки — в [docs/BUILDING.md](docs/BUILDING.md).
- «Нет сети» — `HTTPS_PROXY=http://127.0.0.1:9`, без правки системных
  настроек.
- Не вводи логины, пароли и токены: вход делает только человек.

## Перед тем как отдать PR

Десктоп:

```sh
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
```

Android (в `android/`):

```sh
./gradlew :app:testDebugUnitTest :app:assembleDebug
```

Затем просмотри свой diff (`git diff`) по списку:

- [ ] нет записи звука на диск, кроме явного «Скачать»;
- [ ] плеер не может стартовать без подтверждённой подписки;
- [ ] токен не попадает в файл, лог, `Debug`, ошибку или URL;
- [ ] нет паник, индексации, срезов и `as` с потерей данных;
- [ ] ошибки сети показываются пользователю, а не роняют приложение;
- [ ] нет записи в аккаунт без действия пользователя;
- [ ] нет новых хостов и зависимостей без описания в PR;
- [ ] diff содержит только то, что нужно для задачи;
- [ ] комментарии на русском, документация обновлена.

В описании PR честно напиши, что PR подготовлен с помощью ИИ, каким
инструментом, и что человек проверил руками. Это нормально, но ревьюер
должен знать.

## Если ты Claude Code

Claude Code читает `CLAUDE.md`, а не этот файл. Создай в корне свой
`CLAUDE.md` с одной строкой `@AGENTS.md` — он в `.gitignore` и в PR не
попадёт.
