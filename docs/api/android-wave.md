# Android, «Моя волна»: настройки, повтор трека, «Не нравится» — спецификация API

Основа — наша десктопная спека: `docs/api/stage-8.md` (rotor, события обратной
связи, «Не нравится»), раздел 4 `docs/api/stage-9.md` (настройки волны как
seeds) и код `src/api/rotor.rs`, `src/api/wave_settings.rs`,
`src/ui/library/wave.rs`. Живых запросов для этой спеки не делалось: ниже
только то, что уже проверено или принято для десктопа. Формат seeds вживую не
проверен и там (см. «Что проверить вживую»).

## Общее

- База: `https://api.music.yandex.net`. Заголовки у всех запросов:
  `Authorization: OAuth <токен>`, `X-Yandex-Music-Client: YandexMusicAndroid/24023621`
  (в Kotlin это `YandexApi.get`/`post`). Токен не попадает ни в URL, ни в тело
  (кроме заголовка), ни в тексты ошибок и журнал.
- Все три функции — только при подтверждённой подписке: волна и плеер
  существуют лишь после проверки Плюса; запись «Не нравится» дополнительно
  требует `AccountHolder.uid` (он ставится только при Плюсе).
- Настройки волны и повтор — не запись в аккаунт. Запись в аккаунт одна:
  «Не нравится» по явному нажатию кнопки.

## 1. Список занятий

`GET /rotor/stations/list?language=ru`

- Ответ: `{"result":[{"station":{"id":{"type":"activity","tag":"work-background"},"name":"Работа",…},…},…]}`.
- Берём станции с `station.id.type == "activity"`, нужны `id.tag` и `name`
  (подпись от сервиса, русская). Остальные типы (`mood`, `genre`, `epoch`…)
  пропускаем. Непонятный элемент пропускается, повтор тега отбрасывается, не
  больше 60 занятий.
- `tag` идёт в тело `session/new`, поэтому проверяется: 1–64 знака, только
  ASCII-буквы, цифры, `-`, `_`, `.` (`WaveSettings.safeTag`). Название:
  без управляющих знаков, обрезано до 60.
- Не `{"result":[…]}` — ошибка разбора; любая ошибка (сеть, 401/403, 5xx) —
  занятия «не загрузились»: чип «Занятие» скрыт (если занятие не выбрано
  раньше), остальные настройки работают. Повторная попытка — при следующем
  показе экрана волны. Ошибка списка пользователю не показывается.
- Покрытие крейтом `yandex-music`: есть, но крейт не подключён; запрос свой
  (`YandexApi.waveActivities`, разбор — `WaveSettings.parseActivities`).

## 2. Настройки волны → `POST /rotor/session/new`

- Тело то же, что у обычной волны (`docs/api/stage-8.md`), меняется только
  `seeds`:

  | Настройка | Значения | Seed |
  |---|---|---|
  | Занятие | станция из списка | `activity:{tag}` **вместо** `user:onyourwave` |
  | Характер | `favorite` «Любимое», `discover` «Незнакомое», `popular` «Популярное» | `settingDiversity:{значение}` |
  | Настроение | `active` «Бодрое», `fun` «Весёлое», `calm` «Спокойное», `sad` «Грустное» | `settingMoodEnergy:{значение}` |
  | Язык | `russian` «Русский», `not-russian` «Иностранный», `without-words` «Без слов» | `settingLanguage:{значение}` |

  «Любое»/«По умолчанию» — seed не добавляется. Первым всегда идёт seed
  станции (`user:onyourwave` или `activity:…`), затем настройки в порядке
  «характер, настроение, язык» — как `WaveSettings::seeds` на десктопе.
  Пример: `["user:onyourwave","settingMoodEnergy:calm","settingLanguage:russian"]`.
- Когда уходит: при **любой смене выбора** (кроме выбора того же значения —
  тогда ничего), в том числе на экране, где волна ещё не запущена, и когда
  играет чужая очередь. Это новая сессия: очередь заменяется порцией новой
  сессии, играет её первый трек, событие `radioStarted` — как при обычном
  старте. Прежний запуск, если ещё идёт, отменяется (результат не применяется).
- Протухшая сессия (`unknownSession`): новая сессия создаётся с теми же
  seeds (текущие настройки), как на десктопе.
- Хранение: только на устройстве, `SharedPreferences` `plastinka`
  (`Prefs.waveSettings`): `wave_activity`, `wave_activity_name`,
  `wave_diversity`, `wave_mood`, `wave_language`; пустой выбор стирает ключи.
  Неизвестное значение или небезопасный тег при чтении — как будто их нет.
  Выход из аккаунта выбор не стирает (это не данные аккаунта).
- Сброс: «Сбросить» в листе — все четыре настройки в «по умолчанию»,
  запускается обычная «Моя волна».

## 3. «Повторять трек»

- Десктоп: в волне повтор переключается «выкл ↔ трек»; тот же переключатель в
  панели плеера и в полноэкранном плеере; на старте новой волны сбрасывается
  в «выкл»; повтор списков пользователя от волны не зависит.
- Android: режим `REPEAT_MODE_ONE` плеера Media3 (общий для чипа «Повторять
  трек» на экране волны и кнопки повтора в полноэкранном плеере). Включение —
  `PlayerController.toggleWaveRepeat` (выкл ↔ один трек). Новая волна сбрасывает
  повтор в «выкл»; повтор списка, который был до волны, запоминается и
  возвращается при выходе из волны (`playQueue`).
- События волны при повторе — обычная пара, без `skip` (как на десктопе:
  `Finish` и затем новое `trackStarted`): переход с причиной
  `MEDIA_ITEM_TRANSITION_REASON_REPEAT` закрывает прежний проход
  `trackFinished` с `totalPlayedSeconds` = длительность трека, затем
  `trackStarted` для того же `trackId:albumId` с тем же `batchId`.
- «Следующий» при включённом повторе идёт к следующему треку волны (повтор
  остаётся включённым); догрузка порций от повтора не зависит (условие то же:
  впереди не больше двух треков).
- Запросов, кроме событий выше, нет.

## 4. «Не нравится»

Запись в аккаунт по явному нажатию кнопки (решение пользователя; согласие
не нужно).

- Десктоп (`wave_dislike`): трек закрывается событием `skip` (не
  `trackFinished`, даже если доигран), сердце убирается локально (отдельного
  запроса «снять лайк» нет: сервер сам снимает «Нравится»), настоящему треку
  Яндекса (не замене FckCensor) уходит запись в «Не нравится», воспроизведение
  переходит к следующему треку. Очередь не пересобирается: уже загруженные
  треки остаются, догрузка идёт обычным порядком. Ошибка записи — сообщение,
  трек всё равно пропущен. Отмены нет.
- Запрос: `POST /users/{uid}/dislikes/tracks/add-multiple`, форма
  `track-ids=<id>` (`YandexApi.addDisliked`; `id` — цифры, иначе запрос не
  уходит). `uid` — из `AccountHolder` (только при подтверждённом Плюсе: нет —
  кнопка ничего не делает).
- Android: `AppViewModel.dislikeWaveTrack`: убрать сердце локально →
  `PlayerController.skipDisliked` (следующий переход закрывает прежний трек
  событием `skip`: `PlaybackService.markDislike`) → фоновая запись (задача
  отменяется при выходе из аккаунта). Ошибка записи — сообщение «Не удалось
  поставить «Не нравится». Проверьте соединение.» (в журнал — только код
  ответа и id трека), трек пропущен всё равно.
- Последний трек очереди (следующего ещё нет): воспроизведение
  останавливается, у сервиса запрашивается догрузка, при её приходе плеер
  переходит к первому новому треку и играет (на десктопе в этот момент
  «Загружаем волну…»).
- Работает только в волне; для чужих очередей кнопки нет.

## Что проверить вживую

1. Принимает ли `session/new` настройки как seeds вместе с `user:onyourwave`
   и вместо него с `activity:{tag}`; если с занятием настройки игнорируются —
   пробовать `["user:onyourwave","activity:{tag}",…]` (то же открытое место,
   что на десктопе).
2. Меняет ли выбор набор треков волны на практике (разные настроения/язык).
3. `rotor/stations/list?language=ru`: есть ли станции `activity` и какие
   подписи.
4. Что сервер делает с `skip` и записью «Не нравится» вместе; снимается ли
   «Нравится» (сердце убрано локально по десктопу).

## Расхождения

- Десктоп при «Не нравится» на последнем треке показывает «Загружаем волну…»
  и стартует следующий трек автоматически; на Android плеер ставится на паузу
  и стартует сам, когда придёт порция (экрана ожидания нет).
- На десктопе повтор волны — отдельное поле окна; на Android — режим
  `REPEAT_MODE_ONE` плеера с сохранением повтора списка при входе в волну.
