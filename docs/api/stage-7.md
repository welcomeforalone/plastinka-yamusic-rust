# Этап 7: поиск, плейлисты, альбомы, исполнители — спецификация API

Заголовки у всех запросов те же, что на этапах 2–4:
`Authorization: OAuth <token>`, `X-Yandex-Music-Client: YandexMusicAndroid/24023621`.
Хост `https://api.music.yandex.net`. Ответ всегда в обёртке
`{"invocationInfo":{…},"result":…}` или `{"invocationInfo":{…},"error":{"name":…,"message":…}}`.

## Итог

1. Крейт `yandex-music` по-прежнему не подключаем. Его модели строгие:
   `Playlist` требует `playlistUuid`, `cover`, `created`, `ogImage`,
   `owner` и ещё десяток полей (у плейлиста без обложки или из старого API
   разбор всей страницы падает), `ArtistInfo.has_promotions` обязателен,
   `Album.id` разбирается в `u32`. Хуже того, в `search/?text=…` текст
   запроса подставляется в адрес без кодирования: «&», «#», «?» в запросе
   ломают параметры. Разбор свой, мягкий, как на этапе 4: каждый трек,
   альбом, исполнитель и плейлист разбирается отдельно, непонятный
   пропускается (или становится заглушкой «недоступен», если это трек в
   списке, где важен порядок).
2. Треки во всех ответах — та же модель, что в `POST /tracks` (этап 4),
   разбирается той же функцией. К треку добавляем идентификаторы
   исполнителей: по ним строка трека ведёт на страницу исполнителя.
3. Каталог (поиск, альбом, исполнитель, чужой публичный плейлист)
   отвечает и без токена. Поэтому 403 от этих методов — «нет доступа к этой
   странице», а не «токен не действует»: иначе переход на чужой закрытый
   плейлист выкидывал бы на экран входа. 401 и 403 значат «войдите заново»
   только для коллекции пользователя (`users/{uid}/likes/…`,
   `users/{uid}/playlists/list`), как на этапе 4.
4. Текст запроса кодируется как параметр адреса (`reqwest` `query`). Пустой
   и из одних пробелов не отправляем. Длинный обрезаем до 256 символов: сервис
   принимает и 3000, но смысла нет.
5. Ничего не кэшируем на диск: каждый переход — свежий запрос. В памяти окно
   держит открытые страницы, пока по ним можно вернуться кнопкой «Назад».
6. Звук не меняется: плееру нужен только `track_id`, источник очереди ему
   безразличен.

## Поиск: `GET /search`

- Параметры: `text` (строка запроса), `type` — `all`, `track`, `album`,
  `artist`, `playlist` (бывают ещё `podcast`, `video`, `user`), `page` с
  нуля, `nocorrect` — `false` (сервис сам исправляет опечатки).
- `page` не больше 99: на `page=500` — **400** `validate`, «500 must be
  less than 100» (проверено вживую). Дальше 99-й страницы не просим.
- Ответ 200 для `type=all` (живой, сокращён):

  ```json
  {"result":{"text":"король и шут","misspellCorrected":false,"nocorrect":false,
    "searchRequestId":"…",
    "best":{"type":"artist","text":"…","result":{Artist}},
    "tracks":{"total":1269,"perPage":20,"order":3,"results":[Track,…]},
    "albums":{"total":53,"perPage":10,"order":2,"results":[Album,…]},
    "artists":{"total":9,"perPage":10,"order":0,"results":[Artist,…]},
    "playlists":{"total":109,"perPage":4,"order":1,"results":[Playlist,…]},
    "podcasts":{…},"podcast_episodes":{…}}}
  ```

- Для одного типа (`type=track`): `{"type":"track","page":0,"perPage":20,
  "text":…,"tracks":{"total":523,"perPage":20,"results":[…]}}`. Размер
  страницы: треки 20, альбомы 10, исполнители 10, плейлисты 10. В `type=all`
  плейлистов 4 на страницу.
- Ничего не нашлось (`zzqqxxjjvvkk`): 200, в `result` нет ни одного раздела,
  только `text`, `misspellCorrected`, `searchRequestId`.
- Пустой `text`: 200, `"result":"text-is-empty"` — **строка вместо
  объекта**. Не отправляем такие запросы; если пришло, считаем «ничего».
- Опечатка «королль и шут»: `misspellCorrected: true`,
  `misspellOriginal: "королль и шут"`, `misspellResult: "король и шут"`,
  результаты по исправленному. Окно пишет «Показаны результаты по запросу
  «…»».
- Окно ищет по вкладкам: «Треки» (`type=track`), «Альбомы» (`album`),
  «Исполнители» (`artist`), «Плейлисты» (`playlist`). Запрос уходит, когда
  ввод замер на 350 мс, или сразу по Enter. Устаревшие ответы (запрос уже
  другой) отбрасываются по номеру запроса. Следующая страница треков
  догружается, когда список прокручен к концу.

### Подсказки: `GET /search/suggest?part=<текст>`

- Ответ: `{"result":{"best":{"type":"artist","text":"tame impala",
  "result":{Artist}},"suggestions":["tame impala","tame impala currents",…]}}`.
- На этом этапе не используем: результаты обновляются сразу при вводе, и
  список подсказок под полем их бы закрывал. Метод описан на будущее.

## Альбом: `GET /albums/{id}/with-tracks`

- `id` — число (как `albums[0].id` трека). Нечисловой — **404**
  `not-found`. Неизвестный (`999999999`) — **200** с
  `{"id":999999999,"error":"not-found","pager":{…}}`, без `title`.
- Ответ 200 (живой, `10101`, сокращён):

  ```json
  {"result":{"id":10101,"title":"Камнем по голове","year":1996,
    "releaseDate":"1996-05-24T00:00:00+04:00","trackCount":21,"available":true,
    "coverUri":"avatars.yandex.net/get-music-content/7548376/934e66e2.a.10101-6/%%",
    "genre":"punk","metaType":"music","version":null,"type":null,
    "artists":[{"id":41052,"name":"Король и Шут"}],
    "bests":[29238698,29238709,29238706],
    "volumes":[[Track,…]],"pager":{"page":0,"perPage":21,"total":21}}}
  ```

- `volumes` — диски, каждый — массив треков по порядку. Окно склеивает
  диски в один список, номер в строке — сквозной.
- Нужные поля: `id`, `title`, `version` (в скобках), `year`, `type`
  (`single` — «Сингл», `compilation` — «Сборник», иначе «Альбом»),
  `artists[].id/name`, `coverUri`, `trackCount`, `available`, `volumes`.
- Длительность альбома — сумма длительностей треков.

## Исполнитель

### `GET /artists/{id}/brief-info`

- Ответ 200 (живой, `41052`, сокращён):

  ```json
  {"result":{
    "artist":{"id":"41052","name":"Король и Шут","genres":["punk"],
      "cover":{"type":"from-artist-photos","uri":"avatars.yandex.net/…/1d46a945.p.41052/%%"},
      "counts":{"tracks":219,"directAlbums":16,"alsoAlbums":3,"alsoTracks":6},
      "likesCount":6858490},
    "albums":[Album × 9],"alsoAlbums":[Album × 3],"popularTracks":[Track × 10],
    "similarArtists":[Artist × 10],"playlists":[…],"stats":{"lastMonthListeners":6682987},
    "lastReleaseIds":[],"lastReleases":[], …}}
  ```

- `artist.id` здесь строка, в поиске и у трека — число. Принимаем оба.
- Неизвестный исполнитель: **200**, `artist` = `{"id":"999999999",
  "error":"not-found"}`, остальные списки пустые.
- Окно берёт: имя, обложку (`cover.uri`), жанры, `counts.tracks`,
  `counts.directAlbums`, `stats.lastMonthListeners`, `popularTracks`
  (первые 5 в разделе «Популярные треки») и альбомы.

### `GET /artists/{id}/direct-albums?page=0&page-size=100&sort-by=year`

- Все альбомы исполнителя (в `brief-info` только первые 9): `{"pager":
  {"page":0,"perPage":16,"total":16},"albums":[Album,…]}`. При
  `page-size=100` сервис отдаёт все 16 разом. `sort-by` — `year` или
  `rating`. Берём `year`, свежие первыми.
- У исполнителей с сотнями релизов — следующими страницами по 100, не больше
  10 страниц (1000 альбомов).

### `GET /artists/{id}/tracks?page=<n>&page-size=100`

- `{"pager":{"page":0,"perPage":100,"total":219},"tracks":[Track,…]}`.
- `page-size` вплоть до 1000 принимается (`perPage` тогда равен `total`).
  Берём 100: ответ около 230 КБ, 0,35 с. Страница за концом — 200 без
  `tracks`. Так раздел «Все треки» догружается при прокрутке.

## Плейлист: `GET /users/{owner}/playlists/{kind}`

- `owner` — `uid` (число) или логин, `kind` — число.
- Ответ 200 (живой, чарт, сокращён):

  ```json
  {"result":{"uid":414787002,"kind":1076,"title":"Чарт Яндекс Музыки",
    "trackCount":100,"durationMs":19473340,"visibility":"public","available":true,
    "description":"…",
    "owner":{"uid":414787002,"login":"yamusic-top","name":"Яндекс Музыка"},
    "cover":{"type":"pic","uri":"avatars.yandex.net/get-music-user-playlist/51766/chart-…/%%?1705042558734"},
    "tracks":[{"id":154927047,"originalIndex":0,"timestamp":"…","track":Track},…],
    "pager":{"total":100,"page":0,"perPage":100}}}
  ```

- Элемент `tracks` — `{id, timestamp, track}`. С `richTracks=false` (и,
  по сообщениям других клиентов, у очень больших плейлистов) `track` нет,
  только `id` и `albumId`. Тогда данные треков догружаются через
  `POST /tracks` пачками, как «Мне нравится» (этап 4).
- Обложка: `cover.type` — `pic` (`cover.uri`, после `%%` бывает
  `?версия`) или `mosaic` (`cover.itemsUri` — до 4 обложек альбомов, берём
  первую). Нет ни того, ни другого — заглушка.
- Ошибки (проверено вживую): удалённый — **410** `playlist-is-deleted`,
  несуществующий `kind` — **404** `playlist-not-found`. Окно: «Плейлист
  удалён или недоступен».

## Коллекция пользователя (нужен токен)

| Раздел | Метод | Ответ |
|---|---|---|
| Плейлисты | `GET /users/{uid}/playlists/list` | `[Playlist, …]` без треков |
| Плейлисты (понравившиеся чужие) | `GET /users/{uid}/likes/playlists` | `[{"timestamp":…,"playlist":Playlist}, …]` |
| Альбомы | `GET /users/{uid}/likes/albums?rich=true` | `[{"timestamp":…,"album":Album}, …]` |
| Исполнители | `GET /users/{uid}/likes/artists?with-timestamps=false` | `[Artist, …]` |

- `uid` — из `account/status`, как у «Мне нравится».
- Без токена для чужого `uid`: `likes/*` — 200 и `[]`, `playlists/list` —
  200 и публичные плейлисты; для нечислового `uid` — 403
  `ownerOtherwiseUserBindingError`.
- Форма элемента `likes/albums` и `likes/artists` у других клиентов
  описана по-разному: то обёртка `{album}` / `{artist}`, то сам объект.
  Разбор принимает обе формы.
- «Плейлисты» в окне: сначала свои (порядок сервиса), потом понравившиеся.
  Плейлист «Мне нравится» (`kind` 3) в список не попадает: у него свой
  раздел. Один из двух запросов не удался — показываем то, что пришло, и
  сообщение; оба — ошибка раздела.

## Ошибки

| Ответ | Каталог (поиск, альбом, исполнитель, плейлист) | Коллекция |
|---|---|---|
| 401 | Войти заново | Войти заново |
| 403 | «Нет доступа» | Войти заново |
| 404, 410 | «Не найдено» (удалено, нет в каталоге) | Неожиданный ответ |
| 400 | Неожиданный ответ (страница поиска за 99 сюда не попадёт) | Неожиданный ответ |
| 5xx, 429 | Временный сбой, кнопка «Повторить» | Так же |
| Не JSON, `result` не того вида | Непонятный ответ | Так же |
| Сущность с `error` (`not-found`) при 200 | «Не найдено» | — |

## Нужные поля

### Трек

Как на этапе 4 (`docs/api/stage-4.md`), плюс `artists[].id` (число или
строка). Исполнитель без `id` (бывает у `various`) показывается, но ссылкой
не становится.

### Альбом (в списках)

`id`, `title`, `version`, `year`, `type`, `artists[].name`, `coverUri`,
`trackCount`, `available`. Нет `id` или `title` — альбом пропускаем.

### Исполнитель (в списках)

`id`, `name`, `cover.uri` (или `ogImage`), `genres`, `counts.tracks`.
Нет `id` или `name` — пропускаем.

### Плейлист (в списках)

`uid` (или `owner.uid`), `kind`, `title`, `trackCount`, `owner.name`
(или `owner.login`), обложка (см. выше). Нет `uid`, `kind` или `title` —
пропускаем.

## Крайние случаи

- Пустой поиск — экран с подсказкой «Найдите треки, альбомы, исполнителей
  и плейлисты», запроса нет.
- Недоступные треки (нет `available: true`) — серые, пропускаются при
  воспроизведении, как в «Мне нравится».
- Огромный плейлист (тысячи треков) — тот же виртуальный список, что у
  «Мне нравится». Треки без данных догружаются пачками по 250.
- Повторяющийся трек в плейлисте — каждый на своём месте, играющим
  подсвечивается тот, что запущен.
- Быстрые переходы: ответ для страницы, с которой уже ушли, кладётся в её
  запись в истории (если она там ещё есть) или отбрасывается.
- Идентификаторы из ответа попадают в адрес следующего запроса, поэтому
  альбом, исполнитель, `uid` и `kind` — только числа (до 20 цифр), логин —
  только `[A-Za-z0-9._-]` до 64 символов. Остальное ссылкой не становится.

## Расхождения

- Крейт ходит в `artists/{id}` (без `brief-info`). Живой сервис отдаёт
  полный ответ по `brief-info`; его же используют MarshalX и OpenAPI.
- Крейт считает `artist.id` у `brief-info` строкой, у трека — числом; на деле
  бывает и то, и другое.
- OpenAPI описывает `search.result` всегда объектом; на пустой запрос
  приходит строка `"text-is-empty"`.
- У `likes/artists` и `likes/albums` форма элемента в источниках разная
  (см. выше).

## Проверить вживую (с токеном, пользователь)

- «Плейлисты»: свои плейлисты и понравившиеся чужие — все на месте, порядок
  как в официальном клиенте, обложки.
- «Альбомы» и «Исполнители» — понравившиеся, порядок.
- Свой закрытый плейлист открывается, чужой закрытый — «Нет доступа».
- Большой свой плейлист (если есть, 1000+ треков): все треки, скорость.
- Регион `am`: недоступные треки серые.

## Дополнение после приёмки: полезные разделы коллекции

Пользователь попросил сделать «Исполнители», «Альбомы» и «Плейлисты»
полезнее. Адреса взяты из публичного JS веб-клиента music.yandex.ru (тот же
интерфейс у официального настольного приложения; код не переносили, только
пути и форму ответов) и проверены вживую на аккаунте пользователя
2026-11-05: с cookie веб-версии на `api.music.yandex.ru` и с заголовком
`X-Yandex-Music-Client: YandexMusicAndroid/24023621`. С OAuth-токеном на
`api.music.yandex.net` проверяет пользователь в окне.

Страница «Коллекция» веб-клиента — `GET /landing/skeleton/web_collection`:
блоки «Мне нравится», «Любимые исполнители» (`/personal/top/artists/month`),
«Мои плейлисты», «Любимые альбомы», «Тайник» и другие. Раздел
«Исполнители» веб-клиента — «Ваш топ месяца» и «Вам понравились».

**Новые адреса отвечают без обёртки `{"result":…}`** — сам объект. Окно
принимает оба вида (`bare_envelope`).

### Топ месяца: `GET /personal/top/artists/month`

Параметров нет, приходит до 5 исполнителей.

```json
{"artists":[{"artist":{"id":36825,"name":"Radiohead",
  "cover":{"uri":"avatars.yandex.net/get-music-content/…/%%"}},
  "listenTimeSeconds":13110,"top":{"position":1,"progress":"same"}}]}
```

`progress`: `up`, `down`, `same`, `new`. Официальный клиент пишет время
округлённым до получаса: 13110 с — «3,5 часа», 10747 — «3 часа».

### «Встречали в Моей волне»: `GET /landing-blocks/artists?count=N`

`{"items":[{"type":"artist_item","data":{"artist":{id,name,cover}}}]}`.
Состав меняется от запроса к запросу (подборка). Пришло 15 при `count=30`.

### Новые релизы: `GET /landing-blocks/new-releases?count=N`

`{"newReleases":[{"album":{"id","title","albumType","cover":{"uri"}},
"artists":[…],"releaseDate":"2026-10-29T21:00:00+00:00"}]}` — у альбома
`albumType` вместо `type`, обложка в `cover.uri`, исполнители рядом с
альбомом. Релизы персональные (среди них исполнители из коллекции).

### «Собираем для вас»: `GET /landing-blocks/personal-playlists?count=N`

`{"items":[{"data":{"playlist":{"uid","kind","title","cover":{"uri"}},
"playlistType":"playlistOfTheDay","description":"Звучит по-вашему каждый
день"}}]}`. Типы: `playlistOfTheDay`, `neverHeard` («Дежавю»),
`recentTracks` («Премьера»). Плейлист открывается обычным
`GET /users/{uid}/playlists/{kind}` (проверено: «Дежавю», 30 треков).

### Понравившиеся: недавние первыми

- `likes/artists?with-timestamps=true` — у элемента `timestamp`, окно
  сортирует по нему: недавние первыми, как «Вам понравились» у веб-клиента.
- `likes/albums?rich=true` и `likes/playlists` — так же по `timestamp`.
- У веб-клиента есть постраничные `users/{uid}/likes/artists/page` и
  `likes/albums/page` (`page`, `pageSize`, `sort-by`, `sort-order`) — те
  же данные, недавние первыми, `pager.total`. Не используем: старые адреса
  отдают весь список сразу, а значения `sort-by` в JS не нашлись.

### Топ месяца: `GET /personal/top/tracks/month`

«Весь топ» открывает страницу «Топ месяца»: топ исполнителей
(`personal/top/artists/month`) и топ треков месяца. Полного месячного топа
исполнителей у сервиса нет. Проверено вживую (2026-11-13, cookie веб-версии
на `api.music.yandex.ru`):

- `personal/top/artists/month` — всегда 5, параметры (`count`, `limit`,
  `pageSize`) ничего не меняют; `week`, `year`, `all` — 404.
- `personal/top/tracks/month` — 10 треков, параметры тоже не влияют.
  Ответ без обёртки `result` (как у остальных `personal/*`):

```json
{"tracks":[{"track":{"track":{"id":69810,"title":"Flashing Lights",
  "cover":{"uri":"avatars.yandex.net/get-music-content/…/%%"},
  "contentRestrictions":{"available":true,"disclaimers":["explicit"]}},
  "artists":[{"id":644,"name":"Kanye West","cover":{"uri":"…"}}],
  "album":{"id":21078440},"durationMs":237900},"playCount":8}]}
```

  Идентификатор трека — `track.track.id`, альбом — `track.album.id`,
  `playCount` — на уровне элемента. Берём идентификатор и `playCount`,
  полные данные (воспроизведение, обложки, доступность) догружаем
  `POST /tracks` по идентификаторам в порядке топа. Элемент без годного
  идентификатора пропускается, нет `playCount` — 0 (число не показываем).
- `music-history` — всегда 10 последних дней, параметры периода не
  работают. Раньше «Весь топ» считался по ней (сумма длительностей по
  исполнителям), но это другой период, чем «Ваш топ месяца». Заменено на
  `tracks/month`: код подсчёта по истории удалён.
- Страница показывает всё за один период; ошибка любого из двух запросов —
  ошибка страницы с «Повторить».

Проверить вживую: оба адреса на `api.music.yandex.net` с OAuth-токеном
(проверены только с cookie на `api.music.yandex.ru`).

### Не используем

- `music-history` для полок «Недавно слушали»: у пользователя почти всё —
  «Моя волна», поэтому такие полки были бы пустыми. Страница «История»
  ходит к ней отдельно (`src/api/history.rs`).
- «Тайник» (`/landing/block/STASH/smart-open-playlist/MISSED_LIKES`) —
  у пользователя 204 без тела.

### Ошибки

Полки — дополнение: любая их ошибка (сеть, 403, непонятный ответ) просто
убирает полку. Ошибка основного списка — как раньше: 401/403 — снова вход,
остальное — «Не удалось загрузить» с «Повторить». С cookie веб-версии
`likes/albums` и `likes/playlists` иногда отвечали 403
`ownerOtherwiseUserBindingError` («owner must have music sid»); с
OAuth-токеном этап 7 их получал — проверить в окне.

### Проверить вживую (пользователь, в окне)

- «Исполнители»: топ месяца совпадает с официальным клиентом (места,
  стрелки, часы), «Встречали в Моей волне» не пустая, понравившиеся с
  недавних.
- «Альбомы»: новые релизы с обложками; понравившихся у пользователя 0 —
  строка «Отмечайте альбомы сердцем…».
- «Плейлисты»: «Плейлист дня», «Дежавю», «Премьера» открываются и играют;
  «Вы собрали» — «Любимое из VK Музыки».
