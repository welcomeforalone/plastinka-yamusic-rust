# Этап 7.5: плагины — источники данных

Три встроенных модуля: FckCensor, Slopless, CopyTrackName. CopyTrackName в
сеть не ходит. Код аддонов PulseSync, расширения Slopless (GPL-3.0) и скриптов
FckCensorData не смотрели и не переносили. Взяты только формат данных и
поведение.

Разведка — 2026-11-05.

## FckCensor: список `list_v2.json`

### Запрос

`GET https://raw.githubusercontent.com/Hazzz895/FckCensorData/main/list_v2.json`

- Без заголовков и токена. Токен Яндекса сюда не уходит никогда.
- Ответ: `text/plain; charset=utf-8`, около 110 КБ, `Cache-Control:
  max-age=300` и `ETag`. Повторный запрос шлём с `If-None-Match`, ответ 304 —
  список не изменился.
- Читаем не больше 4 МБ. Больше — ошибка «список слишком большой».
- У репозитория нет файла лицензии. Мы данные не распространяем, а берём во
  время работы у пользователя, как сам аддон.
- Схема: `list_v2.schema.json` в том же репозитории (draft 2020-12).

### Нужные поля

```json
{
  "sources": [
    {
      "supportedVersions": ">=2.0.0",
      "tracks": {
        "137472446": { "title": "таблетки" },
        "145054524": {
          "artists": [{ "id": 4952161, "name": "Пошлая Молли" }],
          "coverUri": "t2.genius.com/unsafe/%%/https%3A%2F%2Fimages.genius.com%2F….png",
          "__fckCensor": { "insertionIndex": 2, "audioSourceId": "…" }
        },
        "138629224": { "durationMs": 134034 }
      },
      "albums": {
        "24720439": {
          "title": "…", "artists": [{ "id": 7081546, "name": "zavet" }],
          "coverUri": "avatars.yandex.net/…/%%",
          "volumes": [[{ "id": 110945082 }, { "id": 142464338 }]],
          "__fckCensor": { "replaceArtistsInAlbumVolumes": true }
        }
      },
      "artistsInsertions": { "7081546": { "tracks": [{ "releaseId": "63104735", "index": 0 }] } },
      "tracksStorages": [{ "urlTemplate": "raw.githubusercontent.com/…/tracks/%%", "trackIds": [ … ] }]
    }
  ]
}
```

Что берём:

| Поле | Что делаем |
|---|---|
| `sources[].tracks{id}.title` | название трека вместо цензурного |
| `…tracks{id}.artists[].{id,name}` | исполнители трека |
| `…tracks{id}.coverUri` | обложка (шаблон с `%%`, без `https://`) |
| `…tracks{id}.__fckCensor.audioSourceId` | **замена на трек Яндекса из списка**: звук берётся у трека Яндекса с этим ID (только число, проверка как у любого ID) |
| `…albums{id}.title`, `artists`, `coverUri` | шапка и карточка альбома |
| `…albums{id}.volumes` | состав альбома: ID треков Яндекса по дискам. Треки догружаются через `POST /tracks` |
| `…albums{id}.__fckCensor.replaceArtistsInAlbumVolumes` | исполнители треков альбома = исполнители альбома |
| `…tracksStorages[].trackIds[]` (число или `{id}`) и ключи `tracks{}` | **только как признак** «у трека цензурная версия»: для него ищем версию без цензуры на Яндексе |

Что не берём:

- **Звук из `tracksStorages`** (`urlTemplate` на `raw.githubusercontent.com/…/tracks/%%`,
  значения `tracks{}` и ссылки). Это нелицензионные копии (правило 7):
  адреса не строим и не запрашиваем.
- `durationMs` у трека — длительность файла из хранилища. Мы его не играем,
  поэтому длительность остаётся яндексовской.
- `artistsInsertions` и `insertionIndex` (вставка релизов в профиль
  исполнителя) — пока нет: на странице исполнителя у нас популярные треки и
  альбомы из ответа Яндекса. В бэклог.
- `originalValues`, `notifications`, `supportedVersions` (берём все
  источники).

Разбор мягкий: непонятная запись пропускается, ошибка одной записи не роняет
список. ID — только цифры 1–20, иначе запись пропускается. Тексты чистятся
так же, как ответы Яндекса (`clean`).

### Кэш

`<кэш>/plugins/fckcensor-list.json` — тело ответа и `ETag`. При запуске с
включённым плагином окно сразу берёт кэш и обновляет список в фоне, если
кэшу больше 6 часов. Нет сети — работает по кэшу, без кэша — сообщение в
настройках плагина и кнопка «Повторить». Это только метаданные.

### Обложки с genius.com

17 записей из 61 ведут на `t2.genius.com/unsafe/%%/…`. Хост добавлен к
разрешённым для обложек (`covers::ALLOWED_HOSTS`), правила те же: не больше
2 МБ, только картинки, кэш в `covers`. `%%` заменяется размером `100x100` /
`300x300`, как у Яндекса.

## FckCensor: звук

Порядок, откуда брать звук трека (`queue::sound_id`):

1. Ручная замена пользователя: трек Яндекса или свой локальный файл.
2. `audioSourceId` из списка.
3. Найденная версия без цензуры (автопоиск).
4. Сам трек.

### Автопоиск версии без цензуры

Ищем, только если трек «цензурный»: он есть в списке (ключ `tracks` или
`trackIds` хранилища) или у него `contentWarning: "clean"`. Запрос — уже
существующий поиск каталога:

`GET https://api.music.yandex.net/search?text=<исполнитель название>&type=track&page=0&nocorrect=false`
(подробности в `docs/api/stage-7.md`).

Кандидат подходит, если:

- `contentWarning == "explicit"`, `available == true`, другой ID;
- совпадает хотя бы один исполнитель (по ID, а без ID — по имени без
  регистра);
- название после нормализации (нижний регистр, «ё» → «е», без знаков
  препинания и звёздочек) совпадает или одно начинается с другого;
- длительность отличается не больше чем на 10 с (если обе известны).

Из подходящих — с ближайшей длительностью. Результат (найдено или нет)
кэшируется в памяти и в `<кэш>/plugins/fckcensor-explicit.json` на 30 дней.
Поиск ограничен 10 с; ошибка или таймаут — играет сам трек, без сообщения.

Поле `contentWarning` есть у трека в `/tracks`, поиске, альбоме
(`yandex-music` 0.7: `model/track/mod.rs`, `content_warning: Option<String>`).
Значения: `explicit`, `clean`, нет поля.

### Ручная замена «Заменить на…»

Диалог из меню трека. В поле — запрос или ссылка:

- ссылка `https://music.yandex.ru/album/<a>/track/<t>`, `…/track/<t>`, домены
  `music.yandex.ru|com|by|kz|uz`, с `http(s)://` и без — берём `<t>`,
  трек запрашиваем `POST /tracks`;
- иначе — поиск треков (первая страница).

Выбранный трек — замена. Свой файл — системный диалог выбора файла (`rfd`),
форматы MP3, FLAC, OGG/Vorbis, WAV, M4A/AAC. Замены лежат в
`<настройки>/replacements.toml`:

```toml
[tracks.137472446]
track = "142464338"
title = "Исполнитель — Название"

[tracks.150598645]
file = "D:\\Music\\track.flac"
```

Файл только читается в память плеером (правило 1: аудио на диск не пишем).
С тестовыми хуками файл замен не пишется.

## Slopless

Публичный API без ключа: `https://slopless.art`, описание —
`https://slopless.art/openapi/v1.json` (OpenAPI 3.1, ASP.NET, «Slopless.Api |
v1»). Условий использования и лимитов на сайте нет. Расширение Slopless под
GPL-3.0, его код не смотрели.

### `GET /api/artist/{id}`

- `id` — int32. Заголовок `Accept: application/json`. Токен Яндекса не
  передаётся.
- Ответ:

```json
{"id":24092397,"name":"VANTOR","monthlyListeners":60501,"likesCount":45,
 "aiTracks":4176,"totalTracks":6914,
 "aiTrackList":[{"id":149592201,"title":"…","score":0.99998}],
 "yandexAiTracks":0,"yandexCheckedTracks":0,"yandexAiTrackList":[]}
```

- Числа могут прийти строкой (схема: `["integer","string"]`).
- 404 — исполнителя нет в базе: «не знаем», не «человек».

Как читаем:

- **ИИ-исполнитель** — `aiTracks * 2 >= totalTracks` и `aiTracks > 0`, то
  есть не меньше половины треков. Порог наш: API даёт только счётчики.
- **ИИ-трек** — его ID есть в `aiTrackList` (там треки с `score >= 0.3`, порог
  из описания API) или в `yandexAiTrackList` любого исполнителя трека.
- Список ИИ-треков исполнителя храним не длиннее 20 000 ID. Ответ читаем не
  больше 8 МБ (у VANTOR около 300 КБ).

### `GET /api/track/{id}`

`{"id":…,"title":…,"score":3.1e-05,"scoreYandex":0,"album":{…},"artists":[…]}`.
`score = -1` или `null` — трек не оценён. Не используем: запрос на каждый
трек — сотни запросов на список. Хватает запроса на исполнителя.

### Запросы и кэш

- Спрашиваем исполнителей видимых строк и трека в плеере, не больше 4
  запросов сразу, таймаут общего клиента.
- Кэш `<кэш>/plugins/slopless.json`: на исполнителя — флаг и ID ИИ-треков,
  время ответа. Живёт 7 дней. 404 тоже кэшируется. Ошибка сети не
  кэшируется, повтор при следующем показе, но не чаще раза в минуту.

### Автопропуск и «не нравится»

- Автопропуск (по умолчанию включён вместе с плагином): ИИ-трек считается
  недоступным для очереди. Если ответ пришёл, когда трек уже играет, —
  переходим к следующему.
- «Не нравится» — только после отдельного согласия в диалоге (запись в
  аккаунт). Ставится пропущенному ИИ-треку, один раз за сеанс:

`POST https://api.music.yandex.net/users/{uid}/dislikes/tracks/add-multiple`

- Заголовки: `Authorization: OAuth <токен>`, `X-Yandex-Music-Client`.
- Форма: `track-ids=<id>[,<id>…]`.
- Ответ: `{"result":{"revision":N}}`. Ошибки: 401/403 — вход заново, сеть —
  сообщение «Не удалось поставить «Не нравится»…».
- Крейт: `api/track/add_disliked_tracks.rs` (тот же путь и поле формы).
  MarshalX: `users_dislikes_tracks_add`.

## CopyTrackName

Формат из настроек, по умолчанию `{artist} — {title}`. `{artist}` —
исполнители через запятую, `{title}` — название с версией, `{album}` —
альбом. Неизвестные `{…}` остаются как есть. Пустой формат — по умолчанию.
Пишется в буфер обмена через `iced::clipboard::write`. С FckCensor копируется
название без цензуры.

## Расхождения и что проверить вживую

- `contentWarning` в ответе поиска с настоящим токеном: из-за кодировки
  кириллицы в curl живой ответ без токена получить не удалось. По крейту и
  ответам альбома (`/albums/{id}/with-tracks`: `"contentWarning":"explicit"`)
  поле на месте.
- Есть ли у Яндекса explicit-версии для треков из списка: часть цензурных
  треков в каталоге только в одной версии. Тогда автопоиск ничего не находит,
  и играет сам трек.
- Как часто 404 у Slopless для обычных исполнителей.
- Срабатывает ли `If-None-Match` у raw.githubusercontent.com (ETag есть).
