# Android, этап «Настройки», шаг 3в: плагины (спецификация)

Основа — наша десктопная спека `docs/api/stage-7.5.md` и код `src/plugins/`.
Живых запросов для этой спеки не делалось: всё ниже опирается на проверки,
сделанные для десктопа. Код аддонов PulseSync и расширения Slopless (GPL) не
смотрели и не переносили.

## Общее

- Три плагина на странице «Настройки → Плагины», все **выключены по
  умолчанию** (кроме вложенного «Пропускать ИИ-треки»: он включён, но
  действует только при включённом Slopless, как на десктопе). Настройки лежат
  в `SharedPreferences` `plastinka` (`data/Prefs.kt`, ключи `plugin_*`).
- Выключенный плагин не делает запросов и ничего не меняет в интерфейсе и
  звуке.
- Запросы плагинов к GitHub и slopless.art собираются отдельно
  (`data/PluginHttp.kt`): без токена Яндекса, только `User-Agent:
  Plastinka/0.1 Android` и `Accept: application/json`. Ответ читается не
  больше лимита (8 МБ), больше — ошибка.
- На диск — только метаданные (кэши Slopless, списка FckCensor и найденных
  explicit-версий в `cacheDir/plugins`). Звук на диск не пишется.

## 1. FckCensor

`GET https://raw.githubusercontent.com/Hazzz895/FckCensorData/main/list_v2.json`

- Читаем `sources[]`: у каждого источника `tracks{}`, `albums{}` и
  `tracksStorages[]`. Разбор — `data/FckCensorList.kt` (`CensorList.parse`),
  правила те же, что в `parse_list` десктопа (`src/plugins/fckcensor.rs`).
  Не JSON или нет `sources` — список повреждён; непонятная запись (не объект,
  ключ не число) пропускается, остальное работает. Если один и тот же номер
  встретился в нескольких источниках, побеждает последний. Ссылки хранилищ:
  только `https://`, без пробелов, не длиннее 2000 знаков.

### Поля списка

| Поле | Что делаем |
|---|---|
| `sources[].tracks{id}.title` | название трека для показа |
| `sources[].tracks{id}.artists[]` (`id`, `name`) | исполнители для показа; запись без имени пропускается, пустой список — поле не меняется |
| `sources[].tracks{id}.coverUri` | обложка: шаблон без схемы, с `%%` (`t2.genius.com/unsafe/%%/…`), хост из `avatars.yandex.net`, `avatars.mds.yandex.net`, `t2.genius.com`; иначе остаётся обложка Яндекса |
| `sources[].tracks{id}.__fckCensor.audioSourceId` | трек Яндекса, у которого брать звук (обычный поток Яндекса), см. «Звук» |
| `sources[].albums{id}.title`, `artists[]`, `coverUri` | то же для альбома: карточки, шапка, плитки |
| `sources[].albums{id}.volumes` | состав альбома: номера треков Яндекса по порядку, диски подряд (элемент — число, строка или объект с `id`); страница альбома показывает их, см. «Состав альбома» |
| `sources[].albums{id}.__fckCensor.replaceArtistsInAlbumVolumes` | `true` — исполнители этих треков = исполнители альбома из списка |
| `sources[].tracksStorages[]` (`urlTemplate`, `trackIds`, `tracks`) | прямые ссылки на звук; номера треков из хранилищ ещё и признак «у Яндекса цензурная версия» (для автопоиска explicit) |

Пример (сокращён):

```json
{"sources":[{
  "tracks":{"29238706":{"title":"Дурак и молния","artists":[{"id":41052,"name":"Король и Шут"}],
                        "coverUri":"t2.genius.com/unsafe/%%/https%3A%2F%2F…"}},
  "albums":{"10101":{"title":"Камнем по голове","coverUri":"t2.genius.com/unsafe/%%/…"}},
  "tracksStorages":[{"urlTemplate":"raw.githubusercontent.com/…/%%.mp3","trackIds":[500000]}]
}]}
```

### Звук

Решение принимается в одном месте — `FckCensor.resolveSound(api, token, id,
track)`, его зовёт `PlaybackService.resolve` при открытии потока (на потоке
загрузчика Media3; плеер открывает следующий трек заранее, поэтому всё ниже
успевает до его начала). Порядок — как `Censor::sound` на десктопе
(`src/plugins/fckcensor.rs`):

0. **ручная замена** (см. «Ручные замены» ниже) — выше всего остального, как на
   десктопе: свой файл (`FckSound.File`) приоритетнее трека Яндекса
   (`FckSound.Yandex(<номер замены>)`). Плагин выключен — замены не действуют;
1. `tracks{id}.__fckCensor.audioSourceId` — **другой трек Яндекса**; поток
   берётся обычным путём (`get-file-info`, при неудаче `download-info`, то же
   качество из настроек), без проверки доступности самого трека;
2. прямая ссылка из `tracksStorages` (`FckSound.Direct`): только `https`, поток
   читает тот же `OkHttpDataSource`, что и поток Яндекса;
3. если трек недоступен (`available: false`) и звука нет ни по 0, ни по 1–2 — как есть (не
   играет, как раньше). Недоступный трек **с** пунктом 1 или 2 в очереди
   разрешён (с пунктом 0 — тоже): `Track.playable = available || FckCensor.hasSound(id)` (строки,
   `playQueue`, «Недавно играли»; на десктопе `Censor::playable`);
4. **explicit-версия** (см. ниже) для треков с цензурной версией, если включён
   «Искать версию без цензуры» (по умолчанию включён) и плагин включён;
5. сам трек.

Что реально играет, запоминается в памяти (`FckCensor.playingOf`, последние 40
треков очереди; решение сбрасывается при переключении плагина). Остальной код
спрашивает только его:

- значок качества: `QualityHolder.put(<трек очереди>, кодек, битрейт)` — по треку
  очереди, но кодек и битрейт того потока, который играет; прямая ссылка и свой
  файл — `QualityHolder.clear` (на десктопе у своего файла тоже нет значка);
- нормализация: `FckCensor.loudnessOf` — громкость (`r128`) того, что играет:
  у самого трека своя, у другого трека Яндекса — его (из ответа поиска или одним
  запросом `POST /tracks` с `track-ids=<id>` при открытии), у прямой ссылки и пока
  решение не принято, и у своего файла — без поправки (на десктопе у файла
  нормализации тоже нет). На десктопе громкость замены берётся, только
  если трек замены известен; здесь запрашивается. `Normalizer` пересчитывается при смене
  трека и когда решение о звуке принято (`FckCensor.playingVersion`);
- `play-audio` (`FckCensor.reportedId`): шлётся, когда пошёл звук. Если играет
  другой трек Яндекса, отчёт про него (`track-id` замены, без `album-id`
  оригинала), как на десктопе (`report_begin`); про прямую ссылку и свой файл не шлётся;
- смена качества: прямую ссылку и свой файл не перезапускает
  (`FckCensor.playsOutsideYandex`);
- лайк, «Не нравится», события волны и тексты Яндекса — по номеру трека очереди
  (настоящему), как раньше.

Включение на лету: `Prefs.changeFckCensor` → `FckCensor.onToggle()` грузит
список; звук заменяется со следующего открытия потока, названия — сразу.
Играющий трек доиграет как открыт; сброс решений при переключении лишь
выравнивает отчёты и громкость в оставшейся части этого трека.

### Автопоиск explicit-версии

Как `find_explicit` / `pick_explicit` на десктопе.

- Когда: трек доступен, не `explicit` и «цензурный»: `contentWarning: clean`, либо
  номер есть в хранилищах `tracksStorages`, либо в `tracks{}` списка
  (`CensorList.censored`). Только для треков, которые Media3 открывает
  (играющий и подготовленный следующий), не для строк списка.
- Запрос: `GET https://api.music.yandex.net/search?type=track&page=0&nocorrect=false&text=<исполнитель название>`
  (стандартные заголовки Яндекса, как у вкладки поиска; исполнитель — первый из
  `artists` самого трека, название — то, что прислал Яндекс, не подменённое списком).
- Выбор (`ExplicitMatch.pick`): `contentWarning: explicit`, `available`, не сам
  трек, общий исполнитель (по номеру; нет номера у одного из них — по названию), то же
  название после нормализации (регистр, «ё»=«е», только буквы, цифры и `*`;
  одно может быть началом другого; `*` цензуры совпадает с любой одной буквой), разница
  длительности не больше 10 с (если длительность известна у обоих). Из подходящих —
  с ближайшей длительностью.
- Не тормозит старт: ответ из кэша мгновенный; без кэша поток трека ждёт ответ
  поиска **не дольше 10 с** (как `SEARCH_TIMEOUT` на десктопе: там плеер на это
  время молчит). Ошибка, нет сети, таймаут — трек играет как есть, сообщения нет,
  в кэш ничего не пишется (следующий раз поищем снова).
- Кэш `cacheDir/plugins/fckcensor-explicit.json`: `{"found": {"<id>": {"to":
  "<id>" | null, "at": <мс>}}}` — только номера, звука там нет. Живёт 30 дней (запись
  «из будущего» не верим), не больше 5000 записей (старые вытесняются), файл до
  2 МБ. Результат «нет такой» тоже кэшируется. Запись через временный файл и
  переименование, сбой записи не мешает; битый файл — пустой кэш.
- Выключенный плагин или выключенный переключатель — ничего не ищется. Результаты
  кэша от выключенного переключателя не удаляются.
- Если explicit-версия найдена, но её поток получить не удалось, трек не
  играет (запасного возврата к цензурной версии нет, как на десктопе).

### Состав альбома

- Страница альбома (`AppViewModel.loadAlbum`) и кнопка Play у лучшего результата
  поиска берут альбом `albums/<id>/with-tracks`, затем `FckCensor.withAlbumVolumes`:
  если у альбома в списке непустой `volumes`, треки запрашиваются пачкой
  (`POST /tracks`, `track-ids=...`) и ставятся вместо состава Яндекса в порядке
  списка (повторы убираются, отсутствующие в ответе пропускаются). С
  `replaceArtistsInAlbumVolumes` у них исполнители альбома из списка.
- Нет ответа, плагин выключен, альбом не в списке, пустой результат — состав
  Яндекса. Список ещё не пришёл — ждём не больше 3 с. Состав берётся при открытии
  альбома (как на десктопе): включили плагин при открытой странице —
  обновится после повторного открытия.

### Применение подмен

- Одна точка — модель. `Track` и `AlbumCard` хранят то, что прислал Яндекс
  (`sourceTitle`, `sourceArtists`, `sourceCoverUri`), а `title`, `artists`,
  `coverUri`, `artistNames`, `displayTitle`, `coverUrl()` — для показа: они
  спрашивают `FckCensor.trackPatch(id)` / `albumPatch(id)`. Поэтому подмена
  видна везде, где показан трек или альбом (списки, очередь, история,
  поиск, топ, плитки, мини-плеер, полноэкранный плеер, экран волны, шторка,
  `CopyTrackName`, LRCLib), без правок в каждом экране.
- Названием подменённого альбома версия (`Deluxe`) не дополняется (как
  на десктопе). У трека версии в модели нет.
- Переключатель действует сразу: чтение подмены идёт через снимок
  состояния Compose (`revisionState`), включение, выключение и новый
  список перерисовывают экраны. Шторка и экран блокировки: сервис
  воспроизведения подписан на `FckCensor.revision` и обновляет
  `MediaMetadata` элементов очереди на месте (`replaceMediaItem` с тем же
  адресом: ExoPlayer обновляет элемент без перезапуска, звук и позиция не
  сбрасываются).
- Выключенный плагин: `trackPatch`/`albumPatch` отдают `null`, звук не
  меняется, поиск не идёт, список в памяти пуст, сеть не запрашивается.
- Настоящий трек остаётся настоящим: `id` не меняется. По нему идут лайк и
  «Не нравится», события волны и тексты Яндекса; `play-audio` — по треку, который
  реально играет (см. «Звук»). Slopless спрашивает исполнителей и настоящих
  (`sourceArtists`), и показанных (в базе slopless.art настоящие номера;
  метки сводятся: ИИ сильнее «не знаем», «не знаем» сильнее «человека»).
  LRCLib ищет по показанным названию и исполнителю, `CopyTrackName`
  копирует показанное. Локальный журнал прослушиваний (`PlayLog`) хранит
  исходные значения: выключили плагин — старые записи показываются без
  подмены.
- Строки, собранные в момент действия (подпись очереди «Альбом …»,
  заголовок открытого экрана до загрузки карточки), берут название на этот
  момент; после загрузки карточки показывается актуальное.

### Кэш и обновление

- Файл `cacheDir/plugins/fckcensor-list.json`: `{"fetched": <мс>, "body":
  "<текст списка>"}` (только метаданные). Запись через временный файл
  `fckcensor-list.json.tmp` и переименование; не записался — не беда.
- Порядок при включении или старте приложения (плагин включён): память пуста
  → читаем кэш (подмены появляются сразу, без сети) → если кэш моложе 6
  часов, сеть не трогаем; иначе запрашиваем GitHub. Кнопка «Обновить» на
  странице плагина обновляет принудительно.
- Битый кэш (не JSON, нет `fetched`/`body`, список не разбирается, файл
  больше 24 МБ) — промах без ошибки: идём в сеть.
- Нет сети или GitHub ответил ошибкой, а список (из кэша) есть — он работает,
  страница показывает «Замен в списке»; списка нет — `FckState.Failed`
  с кнопкой «Повторить». Часы, ушедшие назад (`fetched` в будущем), —
  кэш считается устаревшим.
- Выключение забывает список в памяти, файл кэша остаётся (метаданные).

### Ручные замены

Как `Replacement` / `Replacements` / `track_from_link` на десктопе
(`src/plugins/fckcensor.rs`, `src/ui/library/plugins.rs`), действуют только при
включённом плагине. Код: `data/FckReplacements.kt`, действия — в `FckCensor`,
меню — `ui/TrackActions.kt`, лист и выбор файла — `ui/TrackReplace.kt`.

- **Хранилище** `filesDir/fckcensor-replacements.json` (не кэш: не пропадает при
  очистке кэша; метаданные, звука нет):
  `{"version":1,"tracks":{"<id трека>":{"track":"<id>","title":"Исполнитель — Название"}
  | {"file":"content://…","name":"имя файла"}}}`. Запись через временный файл и
  переименование (сбой — сообщение «не удалось сохранить», замена до закрытия
  приложения остаётся в памяти). Чтение: битый или больше 2 МБ файл — пустой
  список без ошибки; запись без допустимого номера трека, без допустимого
  `track`/`file` пропускается; `file` принимается только как `content://`; в записи
  с обоими полями побеждает `file` (как `Replacement::sound`). Не больше 5000
  записей. «Сбросить всё» замены не трогает. Подпись и имя файла чистятся от
  управляющих знаков и знаков смены направления, до 300 знаков.
- **«Заменить на…»** (пункт меню «…» трека): нижний лист, поле поиска с
  подстановкой «Исполнитель Название», до 8 результатов. Задержка ввода 350 мс.
  Если ввод — ссылка на трек (`TrackLink.trackId`, как `track_from_link`), запрос
  `POST /tracks` с `track-ids=<номер>`; иначе `GET /search?type=track&text=…`.
  Выбрать нельзя сам трек и недоступные (`available: false`). Ссылка: схема
  `https://` или `http://` (или без неё), хост `music.yandex.{ru,com,by,kz,uz}`,
  с `www.` и без, путь вида `…/album/<id>/track/<id>` или `…/track/<id>`, `?`/`#`
  отбрасываются; номер — только цифры (до 32, не все нули). Чужой домен
  (`music.yandex.ru.evil.example`), ссылка без `/track/<номер>`, обычный текст —
  не ссылка, идёт обычный поиск. Номер, которого нет в каталоге, даёт «Ничего не
  нашлось».
- **«Свой файл…»**: `ActivityResultContracts.OpenDocument` с типами MP3
  (`audio/mpeg`), FLAC, OGG, WAV, M4A (`audio/mp4`, `audio/x-m4a`), AAC.
  Расширения как на десктопе: `mp3 flac ogg oga wav m4a aac`. Выбранный файл
  проверяется по имени (`DISPLAY_NAME`): расширение из списка или MIME `audio/*`,
  иначе «Этот файл не подходит». Сразу берётся
  `takePersistableUriPermission(uri, READ)`; не вышло — сообщение, замена не
  сохраняется. Файл **не копируется и не читается** при выборе; в хранилище
  только адрес `content://` и имя.
- **Чтение при воспроизведении**: `PlastinkaDataSource` принимает `content://`,
  только если адрес есть среди сохранённых замен при включённом плагине
  (`FckCensor.isReplacementFile`), и читает его `ContentDataSource` (только
  чтение потока в память плеера; ни временной папки, ни кэша). `file://`, любые
  другие схемы и чужие `content://` по-прежнему «звук трека недоступен».
- **Файл пропал** (удалён, провайдер недоступен, разрешение потеряно): при
  открытии `FckCensor.checkFile` открывает и сразу закрывает дескриптор; ошибка →
  сообщение ««Название»: Файл замены не найден…» / «Доступ к файлу замены
  потерян: выберите файл заново» / «не читается» (тост), плеер получает ошибку
  `onPlayerError`, `PlaybackService.skipBrokenFile` переходит к следующему треку
  очереди (если следующего нет — остановка). Ошибка следующего (заранее
  подготовленного) трека пропускает его до начала. Другие ошибки плеера не
  затрагиваются. Замена остаётся в списке: пользователь может убрать её или
  выбрать файл заново.
- **«Убрать замену (…)»**: показывается только у трека с заменой; удаляет её и
  `releasePersistableUriPermission` на файл, если тот же файл не нужен другой
  замене. Замена файла другой заменой снимает разрешение на прежний файл так же.
- **Метка «Замена»** (рамка в цвет акцента, как «ИИ» у Slopless): строки треков
  (`TrackRow`), очередь, полноэкранный плеер.
- **Сразу и в очереди**: замена сохраняется в памяти мгновенно, решение о звуке
  трека сбрасывается (`FckCensor.playingOf`). Если трек играет сейчас — он
  начинается заново с нуля с новым звуком (как `restart_if_current`: на
  десктопе `start(index, 0.0)`), прежнее прослушивание закрывается, новое
  начинается (`PlaybackService.restartForReplacement`); если это следующий трек,
  который плеер мог уже открыть, он открывается заново, позиция играющего
  сохраняется. Остальные треки откроются с новым звуком сами.
- **Лайк, «Не нравится», события волны и текст Яндекса** — по настоящему треку
  (текст: Яндекс — по номеру настоящего трека, в том числе для своего файла и
  замены; LRCLib ищет по показанным названию и первому исполнителю, как на
  десктопе). `play-audio` для замены-трека Яндекса — про трек замены, для
  своего файла не шлётся.
- Различие с десктопом: файл хранится как адрес `content://` (на десктопе путь).
  Ограничение системы на число постоянных разрешений (512 на Android 11+, 128
  раньше): при превышении «Не удалось получить постоянный доступ к файлу».

## 2. Slopless

`GET https://slopless.art/api/artist/{id}` — без ключа и без токена.

- Ответ: `aiTracks`, `totalTracks` (число или строка), `aiTrackList[]`
  (`id`, `score`), `yandexAiTrackList[]`. 404 — исполнителя нет в базе
  («не знаем», кэшируется).
- ИИ-исполнитель: `aiTracks > 0` и `aiTracks * 2 >= totalTracks`. ИИ-трек: он в
  `aiTrackList` с `score >= 0.3` или в `yandexAiTrackList`, либо ИИ один из
  исполнителей. До ответа — «Pending», не ИИ.
- Спрашиваем исполнителей видимых строк (`TrackRow`), играющего и следующего
  трека; не больше 4 запросов сразу, очередь до 200, повтор после ошибки не
  чаще раза в минуту. `id` — только цифры.
- Кэш: `cacheDir/plugins/slopless.json` (метаданные), живёт 7 дней, запись
  через временный файл. Читается один раз за запуск, пишется, когда очередь
  опустела.
- Метка «ИИ» — в строке трека и в полноэкранном плеере.
- Автопропуск (`PlaybackService.slopCheck`): ИИ-трек, не выбранный вручную
  (`QueueHolder.chosenId`: нажатие в списке или очереди), пропускается в сторону
  движения; если ответ пришёл, когда трек уже играет, — тоже. Не больше 50
  подряд и не больше длины очереди: дальше трек остаётся на паузе, показывается
  подсказка.
- «Не нравится» (запись в аккаунт): переключатель выключен по умолчанию, при
  включении — диалог согласия с явным текстом (как на десктопе). Отправляется
  только пропущенному ИИ-треку, один раз за сеанс, только при включённом
  плагине и подтверждённой подписке (`AccountHolder.uid`):

`POST https://api.music.yandex.net/users/{uid}/dislikes/tracks/add-multiple`

- Заголовки: `Authorization: OAuth <токен>` (только в заголовке),
  `X-Yandex-Music-Client`. Форма: `track-ids=<id>`. Ошибка — подсказка «не
  удалось поставить», в лог — код ответа.

## 3. CopyTrackName

- Формат по умолчанию `{artist} — {title}`; `{artist}` — исполнители через
  запятую, `{title}` — название, `{album}` — альбом, остальное как есть;
  подстановка за один проход. Пустой формат — по умолчанию, не длиннее 200
  знаков (`data/CopyName.kt`, правила `src/plugins/copy_name.rs`).
- Действие «Скопировать название» — в нижнем листе кнопки «…» (строка трека и
  шапка полноэкранного плеера). Список действий — `ui/TrackActions.kt`
  (`trackActions`); нет действий — кнопки «…» нет. Подтверждение «Скопировано» —
  только до Android 13 (дальше его показывает система).
