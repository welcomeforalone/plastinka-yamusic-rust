# Android, этап «Поиск»: спецификация API

Основа — десктопная спека `docs/api/stage-7.md` (раздел «Поиск») и разбор в
`src/api/catalog.rs`. Живых запросов для этой спеки не делалось: всё ниже
опирается на проверки, сделанные для десктопа. Код MarshalX и других
GPL/LGPL-проектов не переносился.

## Общее

- База и заголовки — как в `docs/api/android-collection.md` (`YandexApi.get`):
  `Authorization: OAuth <токен>`, `X-Yandex-Music-Client`. Токен не попадает
  ни в URL, ни в текст ошибки.
- 401/403 — `UnauthorizedException`, прочие не-2xx — `IllegalStateException`;
  в окне любая ошибка поиска — «Не удалось выполнить поиск. Проверьте
  соединение.» и кнопка «Повторить».
- Разбор мягкий: нет поля — значение по умолчанию, битый элемент списка
  пропускается, остальные остаются.

## `GET /search`

- Параметры: `text` (запрос, URL-кодирование), `type` — `all`, `track`,
  `album`, `artist`, `playlist`, `page` с нуля, `nocorrect=false`.
- `page` не больше 99: на больших номерах сервер отвечает 400 (проверено на
  десктопе). Пустой запрос не отправляется.
- Размер страницы: треки 20, альбомы, исполнители и плейлисты 10; в `type=all`
  плейлистов 4.

### Ответ `type=all`

```json
{"result":{"text":"…","misspellCorrected":false,
  "best":{"type":"artist","result":{Artist}},
  "tracks":{"total":1269,"perPage":20,"results":[Track,…]},
  "albums":{"total":53,"perPage":10,"results":[Album,…]},
  "artists":{"total":9,"perPage":10,"results":[Artist,…]},
  "playlists":{"total":109,"perPage":4,"results":[Playlist,…]}}}
```

- `best.type` — `track`, `album`, `artist` или `playlist`; другое значение
  (podcast, video, user…) или битый `best.result` — блока «лучший результат»
  нет. Объекты разбираются теми же функциями, что и в коллекции
  (`parseTrackSafe`, `parseAlbumCard`, `parseArtistCard`, `parsePlaylistCard`).
- Плейлист в поиске: владелец — `uid` или `owner.uid`, плюс `kind`; без
  любого из них элемент пропускается.
- Ничего не нашлось: 200, в `result` нет ни одного раздела.
- Пустой `text`: 200, `"result":"text-is-empty"` — строка вместо объекта;
  считается пустым результатом.

### Ответ `type=<один тип>`

`{"result":{"type":"track","page":0,"perPage":20,"text":…,"tracks":{"total":523,"perPage":20,"results":[…]}}}` —
нужный блок называется по типу во множественном числе (`tracks`, `albums`,
`artists`, `playlists`).

### Подгрузка

Следующая страница есть, если на странице пришёл хотя бы один элемент, блок
сообщил `perPage` и `total`, и `(page + 1) * perPage < total`, и страница
меньше 99. Иначе API повторно не вызывается. Вкладка «Всё» не листается.

## Поведение окна

- Вкладки «Всё», «Треки», «Альбомы», «Исполнители», «Плейлисты» — у каждой
  своё состояние (загрузка, ошибка, список, страница). Запрос уходит только
  для открытой вкладки; остальные загружаются при первом открытии.
- Выбор вкладки переживает смену запроса. Смена запроса сбрасывает данные
  всех вкладок и отменяет текущие запросы.
- Пауза ввода 350 мс (debounce); ответ с прежним номером запроса
  отбрасывается.
- Кнопка Play у лучшего результата: трек — сам трек; альбом
  (`albums/{id}/with-tracks`), плейлист (`users/{uid}/playlists/{kind}`),
  исполнитель (`artists/{id}/brief-info`, популярные треки) — загружаются
  существующими методами. Сбой тихо оставляет прежнюю очередь.

## Что проверить вживую

- Формат `best` (особенно `result` у типа `playlist` и `track`) — пересказан
  из десктопной спеки, на Android не проверялся.
- Что `perPage`/`total` приходят в блоке выбранного типа у `type=track` и
  др. (десктоп это подтверждает).
- Влияние `nocorrect=false` на результаты с опечатками.
