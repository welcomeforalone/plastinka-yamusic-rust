# Android, этап «Плеер», шаг 2а: качество потока и тексты песен

Основа — наша десктопная спека `docs/api/stage-9.md` (разделы 1–3) и код
`src/api/lyrics.rs`, `src/lyrics/` (`mod.rs`, `lrc.rs`, `lrclib.rs`). Живых
запросов для этой спеки не делалось (токена у агента нет): всё опирается на
проверки, сделанные для десктопа.

## Общее

- Яндекс: `Authorization: OAuth <токен>`, `X-Yandex-Music-Client:
  YandexMusicAndroid/24023621`. Токен уходит только на `api.music.yandex.net`.
  Файл с текстом (другой хост) и LRCLib запрашиваются **без токена**, в
  отдельных `Request`, не через `YandexApi.get`.
- LRCLib: `User-Agent: Plastinka/0.1 Android`, авторизации нет.
- Токен не попадает в URL, лог и текст ошибки; все сообщения — константы на
  русском.
- Идентификатор трека идёт в адрес: только цифры (`YandexApi.isNumericId`).
- Ошибка сети — понятный текст с кнопкой «Повторить», приложение не падает.
- Звук здесь не участвует. Кэш — **только в памяти**, на диск ничего не пишется.

## 1. Значок качества

Данные уже есть в `StreamResult.Url(url, kbps, codec)`: `codec` и `bitrate` из
`get-file-info` (`aac-mp4`, `aac`, `mp3`, `flac`, `flac-mp4`) либо `mp3` и
`bitrateInKbps` запасного `download-info`.

- `PlaybackService.resolve` при получении ссылки кладёт `trackId → (codec,
  kbps)` в `QualityHolder` (в памяти, последние 20 треков). Ссылка в держатель и
  в лог не попадает.
- Замена FckCensor или неудача получения потока — запись трека удаляется
  (значка нет).
- Подпись как на десктопе (`quality_text`): `FLAC` (без битрейта), `AAC · 256`,
  `MP3 · 320`; битрейт 0 — только название кодека; неизвестный кодек — значка нет.
- Плеер показывает значок для текущего трека; место под ним занято всегда.
- Что потоком играет именно то, что в держателе: ссылка получается в момент
  открытия источника, значок появляется вместе с началом загрузки.
  Предзагрузка следующего трека кладёт запись заранее — это верно, потому что
  показ идёт по id текущего трека.

## 2. Текст Яндекса

`GET /tracks/{id}/lyrics?format=LRC|TEXT&timeStamp={секунды}&sign={подпись}`

- Подпись: HMAC-SHA256 ключом `SIGN_KEY` от строки `trackId + timeStamp`
  (в таком порядке, без разделителей), base64 стандартный **с «=»**, затем
  кодируется как URL-параметр (`+`, `/`, `=` → `%2B`, `%2F`, `%3D`). Порядок
  обратный `get-file-info`, и «=» не обрезается.
- Ответ: `{"result":{"downloadUrl":"https://…yandex.net/…", …}}`. Ссылка должна
  быть `https` на хост `*.yandex.net` / `*.yandex.ru` (`allowedUrl`), иначе
  «непонятный ответ».
- 401 → «Войдите в аккаунт заново». 404 и 403 → текста нет (не «токен не
  действует»). `{"error":…}` без `result` → текста нет. Нет `downloadUrl` →
  текста нет. Остальные не-2xx → «временно недоступен» (5xx, 429) либо
  «непонятный ответ».
- Файл: `GET downloadUrl` без токена. 404, 403, 410 → текста нет. Не больше
  256 КБ, иначе «непонятный ответ». Из текста убираются BOM и `\r`; пустой —
  «текста нет».
- Порядок форматов: сначала `LRC`. Разобралась хотя бы одна строка с меткой —
  синхронный текст. Пришёл текст без меток — показываем как обычный. Нет
  `LRC` — запрашиваем `TEXT`.
- Признаков наличия текста в данных трека (`lyricsInfo`) Android-разбор не
  читает, поэтому всегда пробуем оба формата; для трека без текста это два
  быстрых ответа 404.

## 3. LRCLib

- `GET https://lrclib.net/api/get?track_name&artist_name[&album_name][&duration]`.
  Нет названия или исполнителя — не спрашиваем (текста нет). Длительность —
  целые секунды (округление), только 1–3600. 200 → запись; **404 — штатное
  «нет»**, затем запасной ход.
- Запасной ход: `GET /api/search?track_name&artist_name` (альбом не шлём),
  ответ — массив записей. Берётся запись, у которой длительность в пределах
  ±2 с, с метками предпочтительнее, затем ближайшая по длительности. Нет нашей
  длительности — берётся первая с текстом; нет длительности у записи при
  известной нашей — запись не берётся.
- Запись: `plainLyrics`, `syncedLyrics` (`null` или пустое — нет),
  `instrumental`, `duration`. `instrumental: true` → «Без слов». `syncedLyrics`
  без разобравшихся меток — как обычный текст; нет ни одного — «текста нет».
- 429 → «Текст недоступен: сервис LRCLib просит подождать. Повторите позже»
  (без повторов). 5xx → «Сервис текстов LRCLib временно недоступен». Ответ
  больше 1 МБ — «непонятный ответ».

## 4. Выбор источника и кэш

- Порядок источников — `LyricsRepository.SOURCE_ORDER` (по умолчанию Яндекс,
  затем LRCLib); на этапе настроек станет настраиваемым.
- Как на десктопе (`resolve`): найденный текст любого источника сразу
  возвращается — если у Яндекса только обычный текст, а у LRCLib есть синхронный,
  показывается обычный (LRCLib при найденном тексте Яндекса не спрашивается).
  Иначе: «без слов» важнее ошибки, ошибка важнее «текста нет» (сбой одного
  источника не выдаётся за отсутствие текста), и только потом «текста нет».
- Кэш — `LinkedHashMap` в памяти, до 30 треков (LRU), хранит найденный текст,
  «без слов» и «текста нет». Ошибки не кэшируются. После закрытия приложения
  кэш пуст.
- Запросы — через `Call.enqueue` с отменой при отмене корутины: смена трека
  при открытом экране отменяет загрузку прежнего трека, её ответ не
  показывается.

## 5. Разбор LRC (`LrcParser`)

Перенос логики `src/lyrics/lrc.rs` (наш код) без Android-зависимостей.

- Метка `[мм:сс]`, `[мм:сс.х]`, `[мм:сс.хх]`, `[мм:сс.ххх]`, `[мм:сс:хх]`;
  минуты до 6 цифр, секунды до 4; дробная часть: `5` → 500 мс, `50` → 500,
  `500` → 500, цифры после третьей отбрасываются.
- Несколько меток подряд делят один текст (`[00:12.00][01:30.50] Припев` →
  две строки). Пустой текст — пауза, строка остаётся.
- Метаданные (`[ar:…]`, `[ti:…]`, `[offset:…]`) и строки без меток
  пропускаются, как и битые (`[00:02.00 сломана`). BOM в начале и `\r` в
  конце строк терпятся. Посословные метки `<мм:сс.хх>` убираются.
- Сортировка по времени устойчивая. `activeLine(lines, position)` — индекс
  последней строки с меткой не позже позиции (двоичный поиск), до первой
  строки — `null`.

## 6. Экран текста (поведение)

- Строка подписи: «Текст: Яндекс · синхронный», «Текст: LRCLib · без
  синхронизации» и т. п.
- Автопрокрутка: текущая строка подводится к верхней трети области текста
  (`animateScrollBy`, 450 мс). Пока пользователь держит или листает список,
  автопрокрутка молчит; через 3 с после отпускания пальца и окончания
  инерционного скролла текущая строка возвращается на место. Нажатие на строку
  перематывает на её время и сразу возвращает автопрокрутку.

## Что проверить вживую

- Формат `LRC`/`TEXT` и подпись для Android-клиента (на десктопе проверялись
  для `YandexMusicDesktopAppWindows`); приемлемость `YandexMusicAndroid/…`
  в заголовке.
- Реальные значения `codec` и `bitrate` в `get-file-info` для значка.
- Поведение `animateScrollBy` у конца списка, длинные строки, паузы.
- Лимит LRCLib (около 90 запросов в минуту): при быстром листании треков.
