# Этап 6: воспроизведение потоком — спецификация API

Заголовки запросов к API те же, что на этапах 2–4:
`Authorization: OAuth <token>`, `X-Yandex-Music-Client: YandexMusicAndroid/24023621`.
К хостам хранилища (сам звук и `downloadInfoUrl`) токен **не передаём**: ссылки
подписаны и без него.

## Итог

1. Три шага: `GET /tracks/{id}/download-info` → список вариантов; у
   выбранного варианта `GET downloadInfoUrl` → XML с `host`, `path`, `ts`, `s`;
   прямая ссылка `https://{host}/get-mp3/{md5}/{ts}{path}`, где
   `md5 = MD5("XGRlBW9FXlekgbPrRHuSiA" + path без первого «/» + s)` в
   шестнадцатеричном виде.
2. Берём только `codec: "mp3"` и `preview: false`, наибольший битрейт (обычно
   320). Нет такого варианта — трек недоступен для прослушивания (без Плюса
   сервис отдаёт только 30-секундный `preview`).
3. Хранилище понимает HTTP Range (`206`, `Content-Range`), за пределами файла
   отвечает `416`. Поток читаем в память: один запрос на весь файл, при
   перемотке за скачанное — новый запрос с `Range: bytes=N-`.
4. MarshalX пишет, что ссылка живёт около минуты, потом `410`. Вживую
   прямая ссылка (preview) работала и через 15 минут, а `downloadInfoUrl`
   через 20 минут отвечал `401`. Поэтому на ошибку 4xx повторного запроса
   ссылку получаем заново (шаги 1–3, до 3 раз подряд, пока хранилище не
   примет новую) и продолжаем с того же байта.
5. Крейт `yandex-music` по-прежнему не подключаем (`docs/api/stage-4.md`).
   В нём для XML нужен `serde-xml-rs`, а в подписи `path.get(1..).unwrap()`.
   Запросы свои; XML из пяти плоских тегов разбираем сами.
6. **Правило 1.** Аудио нигде не пишется на диск: байты лежат в `Vec<u8>` в
   памяти сеанса трека и освобождаются при переключении трека. HTTP-кэша у
   reqwest нет, `tempfile` не используется.

## `GET https://api.music.yandex.net/tracks/{id}/download-info`

- Параметры: нет. `id` — идентификатор трека из «Мне нравится» (число или
  UUID, проверка как на этапе 4).
- Ответ 200:

  ```json
  {"result":[{"codec":"mp3","gain":false,"preview":false,
    "downloadInfoUrl":"https://…/get-mp3/…?sign=…&ts=…",
    "direct":false,"bitrateInKbps":320}]}
  ```

  Проверено вживую 2026-11-04 без токена: один вариант `mp3`,
  `preview: true`, `bitrateInKbps: 128` (30 секунд, 481 115 байт). С токеном
  и Плюсом ожидаем `mp3` 320 с `preview: false`, возможно ещё `aac` —
  проверить при приёмке.
- `direct` ни крейт, ни MarshalX не используют. Считаем, что
  `downloadInfoUrl` всегда ведёт на XML.
- Ошибки (вживую):

  | Запрос | Ответ |
  |---|---|
  | `id = abc`, `0` | `400` `illegal-argument` |
  | `id = 2147483648` | `400`, `{"result":{"name":"track-download-info-error","message":"not-found"}}` |
  | UUID несуществующего трека | `404`, то же `not-found` |

  `result` не массив (объект с `name`) — трек недоступен.
- Наши решения по кодам: `401` — токен не действует; `400`, `403`, `404` —
  трек недоступен (не «выйти из аккаунта»: `403` здесь может значить «нет
  прав на трек»); `5xx`, `429` — временный сбой; прочее — неожиданный ответ.

## `GET downloadInfoUrl`

- Адрес из ответа выше, без токена. Проверяем: `https`, хост оканчивается на
  `.yandex.net` или `.yandex.ru`.
- Ответ 200, `application/xml` (вживую):

  ```xml
  <?xml version="1.0" encoding="utf-8"?><download-info><host>s563klg.storage.yandex.net</host>
  <path>/rmusic/U2FsdGVkX1…</path><ts>00065f7992e23d4d</ts><region>-1</region>
  <s>SVvHXQ…X-Wbd0</s></download-info>
  ```

  Заголовка `<?xml …?>` может не быть. Хост встречался и
  `api.music.yandex.net`. С параметром `&format=json` сервер отдаёт то же
  JSON-объектом, но это нигде не описано — не используем.
- Разбор: берём текст тегов `host`, `path`, `ts`, `s`. Проверяем набор
  символов: `host` — латиница, цифры, `.` и `-`, оканчивается на
  `.yandex.net`/`.yandex.ru`; `path` начинается с `/`, только
  `A-Za-z0-9-_/.=~%`; `ts` — шестнадцатеричное число; `s` — base64 для
  адресов, 43 знака: латиница, цифры, `-` и `_`. Иначе — непонятный ответ.
  Сначала здесь стояло «только латиница и цифры», и примерно половина
  треков не включалась: проверено вживую на 17 треках 2026-11-05, `-` или
  `_` в `s` было у 10.

## Прямая ссылка

- `https://{host}/get-mp3/{md5}/{ts}{path}`.
- Ответы хранилища (вживую, preview):

  | Запрос | Ответ |
  |---|---|
  | `HEAD` | `200`, `Content-Type: audio/mpeg`, `Content-Length`, `Accept-Ranges: bytes` |
  | `Range: bytes=0-15` | `206`, `Content-Range: bytes 0-15/481115` |
  | `Range: bytes=999999999-` | `416`, `Content-Range: bytes */481115` |
  | неверный `md5` | `200` — подпись хранилище, похоже, не проверяет |
  | неверный `sign` в `downloadInfoUrl` | `401` |

- Время жизни: см. «Проверено вживую» ниже. На 401, 403, 404, 410 —
  новая ссылка.
- Редиректы разрешаем (до 5, только https): тело запроса пустое, секретов в
  нём нет.

## Поток в памяти

- Буфер сеанса: `Vec<u8>` длиной `Content-Length` (не больше 512 МБ) и
  список скачанных отрезков. Читатель (`Read + Seek` для symphonia) ждёт
  байты на своей позиции. Если позиция далеко за тем, что качается сейчас
  (больше 256 КБ впереди или позади), загрузчик обрывает запрос и начинает
  новый с `Range: bytes=<начало блока 64 КБ>-`.
- Порядок загрузки: от позиции чтения до конца, потом пропуски с начала.
- Перемотка: `SeekMode::Coarse` в symphonia. Для MP3 она прыгает по байтам
  пропорционально времени (нужны `byte_len` и длительность), а не читает
  файл с начала. Поэтому перемотка вперёд не ждёт загрузки всего, что до неё.
- Обрыв сети посреди трека: до 5 повторов подряд без прогресса с паузой
  1, 2, 4, 8, 8 с, каждый с `Range` от первого нескачанного байта. Ответ 4xx
  (ссылка протухла) — ссылку получаем заново, до 3 раз подряд. Новую ссылку
  не дали: токен не принят — вход заново, трек недоступен — следующий трек,
  как в начале. Пока данных
  нет, плеер в состоянии «загрузка», звук молчит, позиция стоит. Повторы
  кончились — ошибка в окне, уже скачанное доиграет.
- Ответ `200` вместо `206` на запрос с середины (сервер не понял Range):
  файл идёт с начала, байты до нужного места пропускаем. Яндекс так не
  отвечает, но без этого загрузка повторяла бы запрос без конца.
- Таймауты: соединение 10 с, чтение 20 с без данных.
- Если читатель ждёт данные, а окно попросило перемотку, ожидание
  прерывается: перемотка не ждёт загрузки старого места. Пока декодер
  разбирает заголовок, чтение не прерываем: перемотку он выполнит сразу
  после разбора.

## Звук

- rodio 0.23 (`default-features = false`, `playback`) — только вывод через
  cpal: свой источник (`Source`) на трек добавляется в микшер устройства.
- symphonia 0.5.5 (`mp3`) — разбор и декодирование в отдельном потоке на
  трек. Декодер кладёт отсчёты в очередь (до 2 с вперёд), источник rodio
  берёт из неё и не блокирует звуковой поток: нет данных — тишина.
- Пауза, громкость и остановка — в источнике, с плавным переходом 10 мс без
  щелчков.
- Источник начинает играть, когда в очереди 0,4 с звука, и после
  опустошения очереди снова ждёт этот запас. Иначе при перебоях данных он
  чередовал бы тишину и обрывки по 20 мс — получался треск.
- В отладочной сборке зависимости собираются с `opt-level = 2`
  (`[profile.dev.package."*"]`): декодер и вывод без оптимизаций в разы
  медленнее.
- Версия symphonia та же, что у rodio (0.5.5), хотя вышла 0.6: декодеры
  rodio выключены, но так в дереве не окажется двух копий, если они
  понадобятся.

## Расхождения

- Крейт и MarshalX строят ссылку одинаково, но крейт помечает
  `download-info` как устаревший в пользу `get-file-info` (подпись HMAC,
  есть lossless). По `CLAUDE.md` на этом этапе — `download-info`, lossless
  позже.
- Хост в XML бывает и `api.music.yandex.net`, и `*.storage.yandex.net`.

## Проверено вживую

- Срок жизни (2026-11-04, ссылка на preview без токена): `HEAD` прямой
  ссылки через 1, 5 и 15 минут — `200`. `downloadInfoUrl` через 21 минуту —
  `401`. Значит, протухает в первую очередь XML-адрес; для полных треков
  с токеном срок не проверен.
- Поддельная тишина (кадры MPEG-1 Layer III из нулей) читается symphonia,
  грубая перемотка в ней работает (тест `silent_mp3_decodes`).

## Проверить при приёмке (нужен токен с Плюсом)

- Какие варианты приходят в `download-info` (есть ли `mp3` 320, `aac`).
- Трек играет, перемотка вперёд за скачанное работает быстро.
- Регион `am`: что приходит для недоступного в регионе трека.
