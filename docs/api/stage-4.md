# Этап 4: «Мне нравится» — спецификация API

Заголовки у всех запросов те же, что на этапах 2–3:
`Authorization: OAuth <token>`, `X-Yandex-Music-Client: YandexMusicAndroid/24023621`.

## Итог

1. Два шага: `GET /users/{uid}/likes/tracks` даёт идентификаторы, затем
   `POST /tracks` пачками даёт данные треков. `uid` берём из `account/status`.
2. Крейт `yandex-music` не подключаем: его модель трека строгая (одно
   неожиданное поле ломает всю пачку), а в разборе `albumId` есть `unwrap` и
   `as u32`. Запросы и разбор свои, мягкие: каждый трек разбирается
   отдельно, непонятный трек становится заглушкой «недоступен».
3. `/tracks` отвечает 400 на всю пачку, если в ней есть хоть один
   неправильный идентификатор. Поэтому идентификаторы заранее проверяем, а на
   400 делим пачку пополам.
4. Кэш на диск на этом этапе не делаем: каждый запуск — свежий список.
   `if-modified-since-revision` пригодится, когда кэш появится.

## `GET https://api.music.yandex.net/users/{uid}/likes/tracks`

- Параметры: необязательный `if-modified-since-revision` (число, по
  умолчанию 0). Смысл в источниках не описан: по названию, ответ только если
  ревизия новее. Пока не передаём.
- Ответ 200:

  ```json
  {"result":{"library":{"uid":42,"revision":1234,
    "tracks":[{"id":"29238706","albumId":"10101","timestamp":"2026-10-01T12:00:00+00:00"}]}}}
  ```

  `id` и `albumId` могут прийти строкой или числом (крейт принимает оба).
  Порядок — как прислал сервер. По наблюдениям других клиентов, сначала
  новые; проверить вживую.
- Без токена (проверено вживую): 403,
  `{"error":{"name":"ownerOtherwiseUserBindingError","message":"owner must have music sid"}}`.
  Считаем 401 и 403 «токен не действует».
- Крайние случаи: пустой `tracks` — пустой список; элемент без `id` —
  пропускаем и сообщаем, сколько пропущено; нет `result.library` —
  непонятный ответ.

## `POST https://api.music.yandex.net/tracks`

- Тело `application/x-www-form-urlencoded`: `track-ids` — идентификаторы
  через запятую, `with-positions=false`. Хвостовая запятая не мешает (так
  делает крейт). Можно и `id:albumId`, но не нужно.
- Работает и без токена: метаданные публичные. Токен всё равно передаём.
- Ответ 200: `{"result":[Track, …]}`. Порядок совпадал с запросом, но
  сопоставляем по `id`.
- Проверено вживую (2026-11-04, без токена):

  | `track-ids` | Ответ |
  |---|---|
  | `7019818,29238706` | 200, два трека |
  | `29238706:3502025` | 200, один трек |
  | `7019818,0f6c8a5e-…-123456789abc` (UUID, как у загруженных пользователем) | 200, второй элемент `{"id":"…","error":"not-found"}` без `title` |
  | `7019818,2147483647` | 200 |
  | `7019818,2147483648`, `…,4294967295`, `…,4294967296` (больше i32) | **400** `validate` на всю пачку |
  | `7019818,0` | **400** на всю пачку |
  | `7019818,007019818` (ведущие нули) | 200 |
  | `7019818,abc` | **400** `validate` на всю пачку |
  | 250 / 1000 / 3000 идентификаторов | 200; 0,6 / 2,1 / 6,7 МБ; 0,9 / 1,4 / 2,7 с |

- Предела на размер пачки не нашли. Берём 250: ответ около 600 КБ, с запасом
  укладывается в таймаут 30 с, и прогресс виден на больших списках.
- Идентификатор считаем правильным, если это число от 1 до 2147483647 (i32) или UUID
  (36 символов, шестнадцатеричные цифры и дефисы). Остальные не
  запрашиваем: сразу заглушка.
- На 400: пачку больше одного трека делим пополам и запрашиваем половины.
  Один трек с 400 — заглушка. На деление тратим не больше 128 лишних
  запросов на весь список, дальше отвергнутая пачка целиком становится
  заглушками.
- Сломанный запрос отличаем от плохих идентификаторов по всему списку, а не
  по одной пачке: больше 32 ответов 400 до первого успешного или ни одного
  успешного ответа на список из нескольких треков — ошибка.
- Идентификаторы попадают в вывод, поэтому берём только строки до 64
  видимых символов ASCII. Остальное, как и элементы без `id`, считаем
  непонятным. Если непонятен весь непустой список — это ошибка, а не «пусто».
- В названиях, исполнителях и альбомах управляющие символы и символы смены
  направления письма (U+202A–202E, U+2066–2069, U+2028/2029) заменяем
  пробелом.

### Нужные поля трека

| Поле | Тип | Как используем |
|---|---|---|
| `id` | строка или число | Ключ сопоставления |
| `title` | строка | Название; нет — «Без названия» |
| `version` | строка | Дописываем в скобках: «Название (Live)» |
| `artists[].name` | строка | Исполнители через запятую; нет — «Неизвестный исполнитель» |
| `albums[0].id`, `albums[0].title` | число, строка | Альбом (первый в списке) |
| `durationMs` | число | Длительность `м:сс` или `ч:мм:сс` |
| `available` | bool | Только `true` — доступен. Нет поля или `false` — недоступен |
| `error` | строка | Есть (`not-found`) — недоступен |
| `coverUri` | строка | Шаблон обложки `…/%%`, для окна на этапе 5 |

Пример (живой ответ, сокращён):

```json
{"id":"29238706","realId":"29238706","title":"Дурак и молния","available":true,
 "availableForPremiumUsers":true,"availableFullWithoutPermission":false,
 "durationMs":114330,"previewDurationMs":30000,"type":"music",
 "coverUri":"avatars.yandex.net/get-music-content/7548376/934e66e2.a.10101-6/%%",
 "artists":[{"id":41052,"name":"Король и Шут","various":false,"composer":false}],
 "albums":[{"id":10101,"title":"Камнем по голове","year":1996,
   "trackPosition":{"volume":1,"index":13}}]}
```

### Ошибки

| Ответ | Результат |
|---|---|
| 401, 403 | Токен не действует |
| 400 | Делим пачку (см. выше) |
| 5xx, 429 | Временный сбой |
| Прочий код | Неожиданный ответ |
| Не JSON, `result` не массив | Непонятный ответ |
| Элемент массива не разбирается | Заглушка для этого трека |

## Крейт `yandex-music` 0.7.0

- `get_liked_tracks(&GetLikedTracksOptions::new(uid))` → `Library { uid,
  revision: u32, tracks: Vec<PartialTrack> }`. У `PartialTrack.timestamp`
  обязательный `DateTime`, `album_id` разбирается с `unwrap()` и `as u32`
  (`model/utils.rs`): отрицательное или дробное число роняет программу.
- `get_tracks(&GetTracksOptions::new(ids))` → `Vec<Track>`. `Track.real_id`
  обязательный: заглушка `{"id":…,"error":"not-found"}` без `realId` ломает
  разбор всей пачки.
- Поэтому крейт не подключаем и на этом этапе.

## Расхождения

- OpenAPI называет поле ревизии `revisions`, крейт и MarshalX — `revision`.
  Берём `revision`, не обязательное.
- OpenAPI считает `albumId` и `timestamp` обязательными у элемента лайков.
  Мы обязательным считаем только `id`.
- MarshalX передаёт `with-positions=True` по умолчанию, крейт — `false`.
  Позиции в альбоме нам не нужны.

## Проверить вживую

Список лайков агент без токена не видел. Пользователю при приёмке:

- `cargo run -- likes`: число треков совпадает с «Мне нравится» в
  официальном клиенте, порядок (сначала новые?);
- недоступные треки помечены;
- загруженные пользователем треки (если есть) — как выглядят.
