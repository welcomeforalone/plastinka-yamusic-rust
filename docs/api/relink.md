# «Искать копию» для недоступных треков

Сервис помечает часть треков `available: false` (права, регион аккаунта,
VPN). Для такого трека окно само ищет на Яндексе тот же трек в другом
релизе (сборник, переиздание, сингл) и играет его. Новых методов API нет:
используется поиск, уже написанный для вкладки «Треки» и для автопоиска
FckCensor (`api::search`, `src/plugins/fckcensor.rs::find_explicit`).

Разведка — 2026-11-21. Кода MarshalX и официального клиента не переносили,
поведение пересказано своими словами.

## Запрос: `GET /search`

`GET https://api.music.yandex.net/search`. Заголовки те же, что у всех
запросов: `Authorization: OAuth <токен>`, `X-Yandex-Music-Client`. Токен в
адрес и в текст ошибки не попадает.

| Параметр | Значение |
|---|---|
| `text` | «первый исполнитель название» (до 256 символов, кодируется как параметр адреса) |
| `type` | `track` |
| `page` | `0` |
| `nocorrect` | `false` (как у вкладки «Треки») |

Ответ `type=track` (подробности — `docs/api/stage-7.md`):

```json
{"result":{"type":"track","page":0,"perPage":20,"text":"…",
  "tracks":{"total":523,"perPage":20,"results":[{
    "id":"29238706","realId":"29238706","title":"Дурак и молния",
    "version":"Remastered","contentWarning":"explicit",
    "artists":[{"id":41052,"name":"Король и Шут"}],
    "albums":[{"id":3095287,"title":"Камнем по голове"}],
    "durationMs":163000,"available":true,"coverUri":"avatars.yandex.net/…/%%",
    "r128":{"i":-9.1,"tp":-0.2},
    "lyricsInfo":{"hasAvailableSyncLyrics":true,"hasAvailableTextLyrics":true}
  }]}}}
```

Нужные поля (все уже разбирает `api::tracks::parse_track`, свой код разбора
не добавляем):

| Поле | Для чего |
|---|---|
| `id` | номер копии; `id` ≠ номер оригинала |
| `title`, `version` | сравнение названия и версии (`normalize`); нет версии — пустая строка |
| `artists[].id`, `artists[].name` | тот же исполнитель (`same_artist`: по номеру, если он есть у обоих, иначе по имени) |
| `durationMs` | длительности отличаются не больше чем на 3 с; без длительности у любого из треков копию не берём |
| `available`, `error` | кандидат должен быть доступен (`available: true` без `error`) |
| `albums[0].id`, `albums[0].title` | альбом копии: сообщение о прослушивании и подсказка в строке |
| `contentWarning` | `explicit`/`clean`: при выборе предпочитаем ту же пометку, что у оригинала |
| `r128` | громкость копии для нормализации |
| `coverUri` | обложка копии, если у оригинала её нет |
| `lyricsInfo` | есть ли текст у Яндекса по номеру копии |

Выбор копии (`relink::pick_copy`): доступный кандидат с другим номером, тот
же исполнитель, название и версия равны после `normalize` (точно, без
«начинается с» и звёздочек цензуры), длительность в пределах 3 с. Из
подходящих — сначала с той же пометкой `contentWarning`, затем с ближайшей
длительностью.

## Крайние случаи

- **Пусто** (`zzqq…`): 200, в `result` нет раздела `tracks`. Копии нет,
  результат «нет копии» кэшируется на 7 дней.
- **Копий нет среди 20 результатов страницы 0**: то же самое. Дальше
  страницы не листаем.
- **Кандидат сам `available: false`** (тот же регион, те же права): не
  подходит. Если подходящих нет — «нет копии».
- **4xx/5xx, нет сети, тайм-аут 10 с, битый ответ**: результат не
  кэшируется ни на диск, ни в память; повтор не раньше чем через 60 с.
- **У оригинала нет названия или исполнителя** (заглушка «не найден»):
  не ищем и не кэшируем.
- Запросы идут не больше чем по 2 одновременно, только для треков в видимых
  строках и следующих 3 треков очереди. Без токена и соединения не ищем.

## Доступность считается для аккаунта

`available` в ответе поиска вычисляется сервером для того аккаунта, чей
токен пришёл в `Authorization` (регион, подписка Плюс, права). Без токена
сервис отдаёт каталог для анонима, и часть треков там недоступна, хотя у
пользователя играет. Поэтому копию ищем с токеном пользователя, а «нет
копии» не переносим между аккаунтами: кэш в каталоге кэша относится к тому
пользователю, чей это каталог (на одном компьютере аккаунт обычно один;
записи живут 7 или 30 дней).

## Поля `substituted`, `matchedTrack`, `realId`

Все три есть в модели `Track` крейта `yandex-music` 0.7
(`src/model/track/mod.rs`): `real_id: String` (обязателен), `substituted:
Option<Box<Track>>`, `matched_track: Option<Box<Track>>`. Крейт ничего не
объясняет: это просто поля модели. По описанию в справке MarshalX (пересказ,
вживую не проверено):

- `realId` — настоящий номер трека в хранилище; у обычных треков равен `id`.
  У нас везде встречался равным `id` (см. примеры в `docs/api/stage-4.md`,
  `stage-8.md`). Заглушка `{"id":…,"error":"not-found"}` приходит без
  `realId`, поэтому крейт на ней падает, а наш разбор — нет. В
  `get-file-info` то же имя — `realId` запрошенного трека.
- `substituted` — вложенный объект `Track`, когда сервер подменил трек
  другим (описан как «подменённый трек»).
- `matchedTrack` — вложенный объект `Track`, подобранный сервером «похожий»
  трек (используется для сопоставления, например при импорте).

В сохранённых ответах репозитория (`stage-4`, `stage-7`, `stage-8`) ни
`substituted`, ни `matchedTrack` не встречаются, как и в ответах поиска и
`POST /tracks`, которые мы разбираем. Доказательств, что они дают доступную
замену недоступного трека, нет, поэтому на них не опираемся: копию ищем
поиском. Если вживую окажется, что у недоступного трека `substituted` или
`matchedTrack` заполнены доступным треком, это можно добавить как первый
шаг до поиска (отдельное решение).

## Что покрывает крейт

Поиск есть в крейте (`yandex-music` 0.7, `search`), но мы его не берём:
у него строгие модели, а текст запроса подставляется в адрес без
кодирования (`docs/api/stage-7.md`). Запрос и разбор — свои, в
`src/api/catalog.rs::search`.

## Кэш на диске (только метаданные, правило 1)

Файл `relink.json` в каталоге кэша. Содержимое — номера, звука нет:

```json
{"tracks":{"137472446":{"copy":{"id":"29238706","album_id":"3095287"},"at":1763700000},
           "138629224":{"copy":null,"at":1763700000}}}
```

- Найдено — свежо 30 дней, не найдено — 7 дней.
- Запись атомарная (временный файл рядом, затем переименование).
- При чтении отбрасываются неправдоподобные номера (не цифры) и устаревшие
  записи; битый файл — как пустой.
- С тестовым хуком `PLASTINKA_TEST_UNAVAILABLE` кэш не читается и не
  пишется.

## Расхождения и что проверить вживую

- Смысл `substituted`/`matchedTrack` взят из справки, не из ответов. Что
  проверить: взять недоступный трек, запросить `POST /tracks`, посмотреть,
  есть ли эти поля и доступны ли вложенные треки.
- Приходит ли для недоступного в регионе трека `available: false` в
  поиске, а у его копии в сборнике — `true`.
- Поиск по «исполнитель название» находит копию на первой странице (20
  результатов). Для очень популярных названий («Intro», «Любовь») копия
  может не попасть на страницу 0 — тогда будет «нет копии».
- Громкость `r128` и `lyricsInfo` у копии есть в ответе поиска (иначе
  нормализация не применяется, текст пробуем запросить).
