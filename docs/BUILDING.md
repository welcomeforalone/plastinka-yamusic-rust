# Сборка из исходников и проверки

## Требования

**Windows:** Rust stable через [rustup](https://rustup.rs) и Visual Studio
(или Build Tools) с компонентом «Разработка классических приложений на C++».
NASM ставить не нужно: `.cargo/config.toml` включает готовые объектные файлы
для TLS-библиотеки aws-lc-sys.

**Linux (Arch, CachyOS):**

```sh
sudo pacman -S --needed base-devel alsa-lib dbus pkgconf
sudo pacman -S --needed libxkbcommon wayland libx11 libxcursor libxi libxrandr vulkan-icd-loader mesa
```

**Linux (Debian, Ubuntu):**

```sh
sudo apt install build-essential pkg-config libasound2-dev libdbus-1-dev
sudo apt install libxkbcommon0 libwayland-client0 libx11-6 libxcursor1 libxi6 libxrandr2 libvulkan1 mesa-vulkan-drivers
```

Для хранения токена в Linux нужен запущенный провайдер Secret Service:
gnome-keyring, KWallet (с включённым Secret Service) или KeePassXC. Без него
вход не сохранит токен и сообщит об этом. ALSA понадобится для звука, D-Bus —
для системного плеера. Вторая строка пакетов нужна окну: оно работает под
Wayland и X11 и рисует через Vulkan (или OpenGL, если Vulkan нет).

Углы окна и мини-плеера в Linux скругляет само приложение (в Windows 11 —
система): окно прозрачное, углы стираются поверх кадра. Развёрнутое и
полноэкранное окно — с прямыми углами. Без композитора с прозрачностью
(X11 без композитора) углы видны чёрными.

Окно рисуется только на видеокарте (wgpu): DX12 в Windows (без поддержки DX12
видеокартой Windows рисует программно, WARP), Vulkan или OpenGL в Linux, Metal
в macOS. Своего программного рендера нет; если видеокарта не запустилась, окно
сообщает об этом. В Linux бэкенд можно выбрать переменной окружения
`WGPU_BACKEND` (`vulkan` или `gl`). На
ноутбуках с двумя видеокартами Plastinka по умолчанию просит встроенную
(`WGPU_POWER_PREF=low`); `WGPU_POWER_PREF=high` включает дискретную.

## Запуск

```sh
cargo run               # окно
cargo run -- --help     # список команд
cargo run -- login      # вход по коду устройства
cargo run -- account    # под каким аккаунтом выполнен вход и есть ли Плюс
cargo run -- likes      # треки из «Мне нравится»
cargo run -- logout     # выход: удалить токен и отозвать его
cargo run -- about      # о программе и где лежат данные
```


## Проверки

```sh
cargo clippy --all-targets -- -D warnings
cargo fmt --check
cargo test
```

В рабочем коде линты в `Cargo.toml` запрещают всё, что может паниковать:
`unwrap`, `expect`, `panic!`, `unreachable!`, `println!`/`eprintln!` (вместо них
`writeln!`), индексацию и срезы (вместо них `get`). В тестах это разрешено
(`clippy.toml`), но только внутри `#[test]` и `#[cfg(test)]`. Поэтому файлы
в `tests/` начинаются с `#![cfg(test)]`.


## Тестовые сценарии

Хуки работают только в отладочной сборке (`cargo build`, `cargo run`). В
релизе их нет.

| Сценарий | Как |
|---|---|
| Не трогать настоящий токен | `PLASTINKA_KEYRING_SERVICE=plastinka-test`: своя запись в хранилище паролей |
| Фальшивый токен | `PLASTINKA_TEST_TOKEN=fake-token-for-tests`: токен берётся из переменной. Хранилище паролей тогда не открывается вовсе: `login` ничего не сохраняет, `logout` ничего не удаляет, окно не пишет в `config.toml` |
| Нет сети | `HTTPS_PROXY=http://127.0.0.1:9` и `HTTP_PROXY=http://127.0.0.1:9` |
| Готовый «Мне нравится» | `PLASTINKA_TEST_LIKES=<имя>` с теми же условиями, что у `PLASTINKA_TEST_STATUS`. Подменяет ответы списка и треков. Имена: `empty`, `sample` (странные и недоступные треки), `many` (1200 треков, пачки и прогресс), `401`, `503`, `broken`, `tracks-400`, `tracks-503`, `tracks-broken`. Для `likes` нужен и `PLASTINKA_TEST_STATUS`, иначе фальшивый токен не пройдёт проверку статуса |
| Поддельный поток | `PLASTINKA_TEST_STREAM=<имя>` с теми же условиями, что у `PLASTINKA_TEST_STATUS`. Ссылка не запрашивается, звук не качается: плеер получает 60 секунд тишины в MP3 (128 кбит/с), собранных в памяти. Имена: `silence` — сразу целиком; `silence-flac` — то же, но в настоящем FLAC, значок качества показывает «FLAC» (проверка значка и панели «Настройки звука» без сети); `broken-aac` — заявлен AAC, но вместо звука мусор: плеер молча повторяет трек как MP3, значок становится «MP3 · 128»; `slow` — медленнее, чем играет (видна загрузка); `flaky` — первый ответ обрывается на 40 %, повтор проходит; `drop` — каждый ответ обрывается на 40 %, после повторов (около 25 с) — ошибка сети; `expired` — обрыв на 30 %, потом ссылка «протухла» до новой; `garbage` — вместо звука HTML; `offline` — ссылку получить не удалось, нет сети; `unavailable` — трек недоступен |
| Готовый каталог | `PLASTINKA_TEST_CATALOG=<имя>` с теми же условиями, что у `PLASTINKA_TEST_STATUS`. Подменяет поиск, альбомы, исполнителей, плейлисты и коллекцию. Страницы собираются для любого идентификатора, поэтому работают все переходы. Обложки не грузятся (заглушки). Имена: `sample`, `empty` (всё пусто), `many` (плейлист на 5000 треков, 400 альбомов, 1990 найденных треков), `slow` (ответ через 1,5 с), `401`, `403`, `404`, `503`, `broken` |
| Плагины без сети | `PLASTINKA_TEST_PLUGINS=<имя>` вместе с `PLASTINKA_TEST_TOKEN`: все пять плагинов включены (в том числе VibeColorizer и YandexMusicTime) (настройки плагинов из `config.toml` игнорируются, окно в него не пишет), вместо GitHub и slopless.art берутся готовые ответы, кэши плагинов не читаются и не пишутся, ручные замены не читаются и не сохраняются. Имена: любое непустое (например `sample`) — список FckCensor из примера (подмены для треков `PLASTINKA_TEST_LIKES=sample`: «Дурак и молния (без цензуры)», «Солистка без цензуры», «Снят с каталога» играет вместо трека `29238706`) и ответы Slopless (исполнители `1001` и `5` — ИИ, у `853465` один ИИ-трек `500001`, `41052` — человек, остальные не найдены); `offline` — нет сети (список не загрузился, Slopless не отвечает); `broken` — ответ не разобрать. Поиск версии без цензуры и поиск в «Заменить на…» идут через `PLASTINKA_TEST_CATALOG`, без него — в сервис с фальшивым токеном |
| YandexMusicTime | Включить плагин в «Настройки → Плагины» (проверять с `PLASTINKA_KEYRING_SERVICE=plastinka-test` и своим входом: с `PLASTINKA_TEST_TOKEN` файл `listen_time.json` не читается и не пишется, статистика живёт только до закрытия). Таймер появляется по центру заголовка и идёт, пока играет трек; пауза и буферизация (`HTTPS_PROXY=http://127.0.0.1:9`) время не считают; свёрнутое окно время считает, серию не отмечает. Смена дня: перевести часы через полночь, таймер «За день» обнуляется, серия растёт; пропуск дня обнуляет серию, рекорд остаётся. Перезапуск: данные сохранились. Битый файл `listen_time.json` переименовывается в `listen_time.broken.json`, статистика пустая. «Статистика»: карточки, неделя по дням, «Скопировать»; «Экспортировать» → «Сбросить» (серия остаётся) → «Восстановить из файла» возвращает время; второе восстановление той же копии ничего не удваивает; файл не из Plastinka — тост, данные целы. Скрытие пункта меню и кнопка «Открыть» в настройках. Огонёк: `PLASTINKA_TEST_STREAK=<число>` (только отладочная сборка и `PLASTINKA_TEST_TOKEN`) подставляет серию и рекорд, проверить 9, 10, 50, 100, 200 и 1000; на диск ничего не пишется. Логика без окна: `cargo test listen` |
| Готовый ответ `account/status` | `PLASTINKA_TEST_STATUS=<имя>` вместе с `PLASTINKA_TEST_TOKEN`: запрос к сервису не идёт, разбирается готовый ответ. Имена: `plus`, `family`, `no-plus`, `no-plus-field`, `region`, `anonymous`, `401`, `503`, `broken`. Пустое значение хук выключает, и запрос идёт к сервису. Хук срабатывает только для токена из `PLASTINKA_TEST_TOKEN`, для любого другого (в том числе выданного при `login`) — ошибка: поддельный Плюс для настоящего токена получить нельзя |
| Обновления без GitHub | `PLASTINKA_TEST_UPDATE_URL=http://127.0.0.1:8000/latest.json` (адрес вместо API GitHub; при хуке разрешены http и любые хосты), `PLASTINKA_TEST_UPDATE_VERSION=0.0.1` (какой версией считать эту сборку), `PLASTINKA_TEST_UPDATE_TARGET=<путь к копии exe>` (что заменять; без неё замены нет, только «скачано и проверено»). Окно запускать с `PLASTINKA_KEYRING_SERVICE=plastinka-test`. Пример ниже |
| Трей, один экземпляр, автозапуск | Тестовые хуки (`PLASTINKA_TEST_TOKEN`) отделяют окно агента от настоящего: блокировка `instance-test.lock`, канал `plastinka-<пользователь>-test` (в Unix `plastinka-test.sock`), а переключатель «Запускать вместе с системой» меняет только состояние в окне: реестр, `~/.config/autostart` и LaunchAgents не трогаются. Значок в трее создаётся и с хуками. Проверка руками (Windows): закрыть окно крестиком — оно скрывается, значок остаётся, музыка играет; левая кнопка по значку возвращает окно; второй запуск `Plastinka.exe` показывает первое окно и сам выходит; «Выход» в меню закрывает всё; `Plastinka.exe --tray` — окна нет, только значок. Без трея (CachyOS в GNOME без расширения или без `StatusNotifierWatcher`) — крестик закрывает программу, строка в настройках неактивна. CachyOS (KDE): значок в системном лотке, пункты меню и подсказка с треком, окно после «Скрыть» открывается заново (Wayland); автозапуск создаёт `~/.config/autostart/Plastinka.desktop`, после перезахода запускается `Plastinka --tray`. macOS: значок в строке меню, крестик прячет окно, «Выход» и Cmd+Q закрывают |
| Скачивание | главное окно с примерами (`PLASTINKA_TEST_LIKES=sample`, `PLASTINKA_TEST_STATUS=plus`), `PLASTINKA_TEST_STREAM=silence` (MP3), `silence-flac` (настоящий `.flac`) или `garbage` (ошибка формата) и `PLASTINKA_TEST_DOWNLOAD_DIR=<папка>` (только отладка: задаёт папку вместо `config.toml`, который с тестовыми хуками не читается и не пишется; без неё первый «Скачать» открывает выбор папки). Сценарии: «Скачать» в меню трека и «⋯» плеера; «Скачать всё» в «Мне нравится»; повтор — «Уже скачан»; отмена выбора папки; папка недоступна. Логика без окна — `cargo test download` |
| Недоступный трек и его копия | `PLASTINKA_TEST_UNAVAILABLE=<id>,<id>`: эти треки считаются недоступными (`available: false`), поэтому поиск копии можно проверить на любом аккаунте. Работает и с настоящим токеном, и с `PLASTINKA_TEST_TOKEN`. Пока хук задан, кэш копий `relink.json` не читается и не пишется, файл прослушиваний тоже не используется. Для «копии нет» взять трек без других релизов. С `HTTPS_PROXY=http://127.0.0.1:9` строка остаётся серой «Недоступен», поиск повторяется не раньше чем через минуту |

Темы (руками, окно с `PLASTINKA_KEYRING_SERVICE=plastinka-test` и
`PLASTINKA_TEST_TOKEN`): перебрать все 12 семейств в тёмном и светлом тоне
и пройти по разделам, диалогам и «Моей волне»; «Как в системе» и
переключение Windows на ходу (Параметры → Персонализация → Цвета → режим);
битые `theme = "abc"` и `theme_mode = 5` в `config.toml`: окно запускается
с «Классикой» и тёмным тоном, остальные настройки целы; полноэкранный
плеер, мини-плеер и «Моя волна» в светлой теме (в первых двух цвета
тёмные); жёлтый и бирюзовый акценты в светлой теме читаются.

Проверка обновления локально (Bash, отладочная сборка). Каталог с файлами:

```sh
mkdir -p /tmp/upd && cd /tmp/upd
cp /путь/к/target/debug/Plastinka.exe ./Plastinka.exe          # «новая версия»
cp /путь/к/target/debug/Plastinka.exe ./target-copy.exe        # что будем заменять
sha256sum Plastinka.exe > Plastinka.exe.sha256                 # формат «<хеш>  <имя>»
cat > latest.json <<'JSON'
{"tag_name": "v9.9.9", "html_url": "http://127.0.0.1:8000/", "draft": false, "prerelease": false,
 "assets": [
  {"name": "Plastinka.exe", "size": 1, "browser_download_url": "http://127.0.0.1:8000/Plastinka.exe"},
  {"name": "Plastinka.exe.sha256", "size": 1, "browser_download_url": "http://127.0.0.1:8000/Plastinka.exe.sha256"}
 ]}
JSON
python -m http.server 8000
```

В другом терминале:

```sh
PLASTINKA_KEYRING_SERVICE=plastinka-test PLASTINKA_TEST_TOKEN=fake-token-for-tests \
PLASTINKA_TEST_UPDATE_URL=http://127.0.0.1:8000/latest.json \
PLASTINKA_TEST_UPDATE_VERSION=0.0.1 \
PLASTINKA_TEST_UPDATE_TARGET=/tmp/upd/target-copy.exe cargo run
```

Сценарии: «Настройки → О программе → Проверить обновления» — «Доступна версия
9.9.9», «Обновить» заменяет `target-copy.exe` (рядом остаётся
`target-copy.exe.old`). «Битый хеш» — испортить хеш в `Plastinka.exe.sha256`:
«Файл обновления повреждён…», копия не тронута. «404» — убрать `latest.json`
(или указать другой путь): «Релиз не найден…». «Нет сети» — запуск без
`PLASTINKA_TEST_UPDATE_URL`, но с `HTTPS_PROXY=http://127.0.0.1:9`: сообщение о
соединении. `PLASTINKA_TEST_UPDATE_VERSION=9.9.9` — «У вас последняя версия».
Логика без окна: `cargo test update`.

Пример (Bash):

```sh
PLASTINKA_KEYRING_SERVICE=plastinka-test PLASTINKA_TEST_TOKEN=fake-token-for-tests cargo run -- account
PLASTINKA_KEYRING_SERVICE=plastinka-test PLASTINKA_TEST_TOKEN=fake-token-for-tests PLASTINKA_TEST_STATUS=no-plus cargo run -- account
PLASTINKA_KEYRING_SERVICE=plastinka-test PLASTINKA_TEST_TOKEN=fake-token-for-tests PLASTINKA_TEST_STATUS=plus PLASTINKA_TEST_LIKES=sample cargo run -- likes
```

Android: отладочного хука для недоступных треков нет, копии проверяются на
настоящем недоступном треке (см. раздел «Android»).

Те же хуки работают в окне (`cargo run` без команды):

| Что увидеть | Переменные (кроме `PLASTINKA_KEYRING_SERVICE=plastinka-test`) |
|---|---|
| Экран входа | ничего (если в `plastinka-test` нет токена) |
| Главное окно с примерами треков | `PLASTINKA_TEST_TOKEN=fake-token-for-tests PLASTINKA_TEST_STATUS=plus PLASTINKA_TEST_LIKES=sample` |
| Длинный список, виртуализация | то же с `PLASTINKA_TEST_LIKES=many` |
| Пустой список | то же с `PLASTINKA_TEST_LIKES=empty` |
| Ошибка загрузки списка | то же с `PLASTINKA_TEST_LIKES=503` или `broken`; `401` возвращает на вход |
| «Нужна подписка» | `PLASTINKA_TEST_TOKEN=fake-token-for-tests PLASTINKA_TEST_STATUS=no-plus` (или `region`, `no-plus-field`) |
| Нет сети | `HTTPS_PROXY=http://127.0.0.1:9 HTTP_PROXY=http://127.0.0.1:9` |
| Воспроизведение без сети и аккаунта | главное окно с примерами треков и `PLASTINKA_TEST_STREAM=silence` (или другое имя). Без этого хука сервис не примет фальшивый токен при запросе ссылки, и окно вернётся на экран входа, как при любом отказе в токене |
| Визуализатор без звука | то же и `PLASTINKA_TEST_SPECTRUM=1`: пока трек играет, визуализатор вместо тишины поддельного потока показывает смесь синусов. Работает только вместе с `PLASTINKA_TEST_TOKEN` |
| Нагрузка визуализатора | спектр и бегущая строка перерисовывают окно 30 раз в секунду, в простое окно не перерисовывается, в свёрнутом тоже (у окна без рамки свёрнутый размер не нулевой, поэтому перерисовку гасит обёртка `pause`). Проверка свёрнутого окна: включить игру с визуализатором, свернуть окно (кнопка «—», панель задач или Win+D), в Диспетчере задач столбец GPU у Plastinka ≈ 0; после разворачивания спектр и бегущая строка продолжают идти. Общая проверка: игра с визуализатором (хуки выше), Диспетчер задач → «Процессы» или «Производительность», столбец GPU; нагрузка не должна расти с частотой монитора. При перетаскивании и растягивании окна спектр идёт 30 кадров/с и не замирает, даже если мышь стоит (таймер потока `drag_pulse`, только Windows) |
| Счётчик кадров | `PLASTINKA_TEST_FPS=1` (только отладочная сборка или `--config profile.release.debug-assertions=true`, с тестовыми хуками): раз в секунду пишет в stderr `кадров: N, сообщений: M, свёрнуто: да/нет` для главного окна (перерисовки считаются и те, что скрывает пауза свёрнутого окна). В свёрнутом окне при игре около 0. Проверка фокуса: в окне при игре со спектром около 30 кадров в секунду, при переключении на другое окно около 1, на паузе без фокуса 0 |
| Поиск, страницы, коллекция | то же и `PLASTINKA_TEST_CATALOG=sample`: в коллекции топ месяца с разными стрелками, «Встречали в Моей волне» (раскрывается «Показать все»), новые релизы, «Собираем для вас», вкладки плейлистов. «Весь топ» — страница «Топ месяца»: 4 исполнителя и 10 треков (`empty` — «Послушайте музыку — здесь появится ваш топ за месяц.») |
| Пустая коллекция | `PLASTINKA_TEST_CATALOG=empty`: «Здесь пока пусто» во всех трёх разделах |
| Большие списки | `PLASTINKA_TEST_CATALOG=many` |
| Углы окна (Linux) | главное окно с любыми хуками: углы скруглены (радиус 8 px при любом масштабе Ctrl + = / −), за ними виден рабочий стол; развернуть двойным щелчком по заголовку — углы прямые, вернуть — снова круглые; то же в полноэкранном режиме окна, с открытым полноэкранным плеером, диалогом и в мини-плеере; ресайз за углы и перетаскивание за заголовок работают. Пример:

```sh
PLASTINKA_KEYRING_SERVICE=plastinka-test PLASTINKA_TEST_TOKEN=fake-token-for-tests PLASTINKA_TEST_STATUS=plus PLASTINKA_TEST_LIKES=sample cargo run
PLASTINKA_KEYRING_SERVICE=plastinka-test PLASTINKA_TEST_TOKEN=fake-token-for-tests PLASTINKA_TEST_STATUS=plus PLASTINKA_TEST_LIKES=sample PLASTINKA_TEST_STREAM=slow cargo run
PLASTINKA_KEYRING_SERVICE=plastinka-test PLASTINKA_TEST_TOKEN=fake-token-for-tests PLASTINKA_TEST_STATUS=plus PLASTINKA_TEST_LIKES=sample PLASTINKA_TEST_CATALOG=sample PLASTINKA_TEST_STREAM=silence cargo run
```

В поддельной тишине длительность 60 секунд, а у примеров треков своя:
трек «кончается» раньше, чем показывает список. Звук слышно только с
настоящим аккаунтом.
